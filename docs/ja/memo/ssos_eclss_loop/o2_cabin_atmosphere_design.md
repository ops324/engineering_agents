# R2 — 酸素をキャビン大気にする（実装前の設計）

2026-08-28。**未実装。** [ROADMAP](../experiments/ROADMAP.md) の R2。
先行文書 [o2_cabin_atmosphere_scoping.md](o2_cabin_atmosphere_scoping.md) の見積もりを、
一次資料の数値で置き換えたもの。**リークは含めない**（R4 に分離済み）。

## なぜ直すか — これは誤りの訂正である

```
388 m³ のキャビンを正常酸素に保つには 105〜112 kg 必要
現行のタンク全量は 8 kg  → キャビン換算で 11.9 mmHg = 窒息水準
```

**物理的にありえない値**である。そして仕組みは正しく動くほど、この土台の上で
確信を持って間違える。EXP-014 の全滅4本（`request_o2` による O₂ 死）は
**8 kg という誤設定が生んだ人工的な死**であり、正しい物理では起きない。

## 一次資料 — [V2 6003] は ppO₂ ではなく PIO2 で規定されている

NASA-STD-3001 Volume 2 Rev D、Table 6.2-1 より（規格本体から直接読んだ）:

```
PIO2 = (PB - 47) x FIO2
   PB   = 周囲気圧 (mmHg)
   FIO2 = 乾燥気体としての O2 モル分率
   47   = 肺内の水蒸気分圧 (mmHg)

  正常酸素 目標帯          145-155 mmHg   (2.80-3.00 psia)   無期限
  無期限 高酸素 上限        356 mmHg       (6.89 psia)        無期限
  短期 高酸素 上限          791 mmHg       (15.30 psia)       6-9時間
  軽度低酸素 下限           127 mmHg       (2.46 psia)        監視付きで無期限
                          （1時間平均。絶対下限 122 mmHg / 2.36 psia）
```

**ppO₂（乾燥分圧）ではない。** 湿度を考慮した吸入分圧である。
`[V2 6004]`（CO₂）が乾燥分圧なのと対照的で、**同じ扱いにはできない。**

### 総圧 760 mmHg 一定と仮定した場合の換算

```
ppO2 = PIO2 x 1.0659

  正常酸素 下限 145 → ppO2 154.6 mmHg → キャビン O2 105.0 kg
  正常酸素 上限 155 → ppO2 165.2 mmHg → キャビン O2 112.2 kg
  軽度低酸素 下限 127 → ppO2 135.4 mmHg → キャビン O2  91.9 kg
  絶対下限     122 → ppO2 130.0 mmHg → キャビン O2  88.3 kg
```

**この仮定は R2 では成立する**（リークが無いので総圧は動かない）。
R4 でリークを入れると総圧が動くので、そこで N₂ が要る。**R2 には要らない。**

## 判断が要る点

### ① 供給とキャビンの境界

OGS が作った O₂ はどこへ行くか。

| 案 | 挙動 | 帰結 |
|---|---|---|
| **A. キャビンへ直接** | OGS → `cabin_o2_kg`。タンクは無くなる | 単純。ただし `request_o2`（在庫から引き出す）の意味が消える |
| **B. タンク経由、手動放出** | OGS → タンク → 放出コマンドでキャビンへ | 操作が1つ増える。**判断の対象も増える** |
| **C. タンク経由、自動補給** | ppO₂ が下限を割ると自動でタンクから補う | 実機に近い。ただし**自動化した部分は腕の判断から外れる** |

**この選択が、シナリオが何を問うかを決める。**
現行の `request_o2` は「在庫から引き出す」サービスで、EXP-014 の全滅4本の原因だった。
A を採ると**このレバー自体が消え、あの失敗モードは二度と起きない**。

### ② 正常酸素帯のどこを初期値にするか

帯の幅は 105.0〜112.2 kg（7.2 kg）で、**乗員4の消費 3.36 kg/day では上端から下端まで 51.7 時間**。
観測窓 16.7時間で消費されるのは 2.34 kg。

```
初期値を上端 112.2 kg にすると  →  16.7時間後も 109.9 kg。帯の中に留まる
初期値を下端 105.0 kg にすると  →  16.7時間後は 102.7 kg。帯を割る（PIO2 141.9 mmHg）
```

**下端から始めれば、何もしなければ観測窓内に規格違反へ落ちる。**
上端から始めれば、O₂ は 50 step のあいだ完全に不活性になる。

### ③ ★ 新しく判明した論点 — 帯を割ったときに乗員を失わせるか

現行のサバイバル規則は `o2_storage_low_kg: 6.0` という**タンク在庫の閾値**で減員を決めている。
キャビン大気にすると、この 6.0 kg には意味が無くなる。

| 案 | 帰結 |
|---|---|
| **A. 規格の帯を減員の根拠にする**（PIO2 127 mmHg 未満が続いたら失う） | 規格と減員が一致する。ただし**帯を割るのに 93 時間**かかるので、50 step では起きない |
| **B. O₂ では減員させない**（規格違反は採点にだけ出る） | **O₂ は「正しいが人を殺さない軸」になる。** CO₂ だけが致死になる |
| **C. 観測窓を延ばす**（50 step → 300 step 以上） | O₂ が生きた軸になるが、**LLM の実行時間が6倍**（1 run 8分 → 50分） |

**B を推す。** A は 50 step では発火せず、C は測定コストが現実的でない。
そして R4 でリークを入れれば、O₂ は**リーク経由で**致死になる。
**O₂ が人を殺す経路はリークであるべきで、代謝ではない** — 108 kg の在庫に対し
乗員4の消費は 32日ぶんであり、代謝で酸素が尽きるシナリオは現実的でない。

## 完成の定義

- `ea score` から `not scored against a standard: o2` が消え、Table 6.2-1 の帯で採点される
- 物理ゲートが通る（酸素の物質収支が閉じる）
- テストが緑（差分で確認）
- ルール腕が生存できる運用点である

# O₂ をキャビン大気にする — 実装前の見積もり

2026-08-26。**実装していない。規模と論点を測っただけ**の文書である。

## なぜ要るか

`reference_limits.py` は O₂ を「名前を付けた、意図的に埋めていない穴」として持っている。

> `plant_sim` の `o2_storage_kg` は `available_o2_kg` — OGS が満たし乗員が引き出す**供給在庫**であって、
> キャビン大気の O₂ ではない。分圧を取るべきキャビン気相の状態が存在しないので、
> どんな数字を入れても [V2 6003] は評価できない。

現実の ECLSS では乗員はキャビンの空気を吸い、効くのは酸素分圧である。タンクと OGS はそこへ供給する側にある。

そして EXP-011 で **O₂ 由来の死者が実際に出た**（`t00_r4`、`o2_warning` 3名）。
いま人が死んでいる軸を、基準に照らして採点できていない。

## 最重要の発見 — 単位を付け替えるだけでは済まない

居住区 388 m³ / 295.15 K で、キャビン大気として O₂ を持つ場合:

```
ppO2 160 mmHg（地上相当 21%）  →  キャビン O2  107.9 kg
ppO2 120 mmHg                  →              80.9 kg
ppO2  90 mmHg                  →              60.7 kg

いまのモデルの タンク全量 8.0 kg を、もし全部キャビンに入れたら  ppO2 11.9 mmHg
```

**8 kg は「キャビン大気」としては窒息水準である。** つまり `available_o2_kg` に別名を付けるだけの変更は成立しない。

逆に、キャビンを現実的な 108 kg にすると:

```
乗員4の消費 0.0467 kg/step × 50 step = 2.33 kg  ＝ キャビン量の 2.2%
108 kg が尽きるまで 2313 step
```

**50 step の run では ppO2 がほとんど動かない。** いまの「タンクが尽きて人が死ぬ」という失敗モードは**消える**。

### したがって、必要なのは2プール模型

```
供給（タンク / OGS） ──流量──> キャビン大気 ──呼吸──> 乗員
```

面白い力学は**供給側と流量**にある。「キャビンは大きな緩衝、供給が追いつかないと分圧が下がる」が物理的に正しい姿で、
失敗モードは「タンク枯渇」ではなく「**供給律速 + リーク or 故障**」になる。

**これはモデルの付け替えではなく、そのシナリオが何を問うているかの変更である。**

### 閾値の単位をどうするか（CO₂ の前例に従えば安く済む）

CO₂ は **キャビン質量 kg** で閾値を持ち、mmHg 換算は採点側（`reference_limits`）でやっている。
O₂ も同じ形にすれば、**単位は kg のまま・参照先だけがタンク→キャビンに変わる**。
84 箇所の多くはそのまま動き、変わるのは**数字の意味と値**になる（6.0 kg → キャビン基準の値）。

mmHg を閾値に持ち込むと、ヘルス・ポリシー・プロンプト・ダッシュボードの単位が全部変わる。**推奨しない。**

## 物理ゲートへの影響（前例あり、軽い）

現在の酸素収支:

```
(貯蔵の増分) == (生成) - (消費 + 外部供給)
```

2プールになれば「貯蔵」を**両プールの和**にする。水の収支が既に `_water_pool_l` で複数プールを合算しており、
**同じ手口がそのまま使える**。導出し直しは必要だが、設計としては既存パターンの適用。

## 人間の判断が要る論点

1. **[V2 6003] の数値レンジが未出典。** 一次資料（OCHMO-TB-003）から読む必要がある。上限（可燃性）と下限（低酸素）の両方
2. **供給とキャビンの境界をどう置くか。** OGS はキャビンに直接吐くのか、タンク経由か。タンクからキャビンへの流量は何が決めるのか
3. **失敗モードを何にするか。** 現行の「タンク枯渇」は消える。代わりにリーク、供給停止、与圧喪失のどれを入れるか（これは故障モデルの強化＝別の課題項目と重なる）
4. **観測期間。** 50 step（16.7時間）ではキャビンの 2.2% しか動かない。ppO2 を動かすには run を長くするか、リークを入れるか
5. **総圧・希釈ガス**（[V2 6006] / [V2 6002]）に踏み込むか。ppO2 だけなら理想気体で足りるが、
   「酸素濃度 %」を語るなら N₂ が要る

## 見積もり

| | 内容 | 規模 |
|---|---|---|
| 機械的 | 状態変数の追加、収支の再導出、ゲート、テスト、docs | **中**（既存パターンの適用が多い） |
| 判断が要る | 上の5論点。特に 2・3・4 は「シナリオが何を問うか」を決める | **ここが本体** |
| 波及 | 全 run が比較不能（世代 v4）。ノイズ床・EXP-009・EXP-011 も測り直し | **確定** |

**「半日で終わる作業」ではない。** 機械的な部分だけなら見通せるが、論点 2〜4 は設計判断であり、
決めずに実装すると「動くが何を測っているか分からないモデル」になる。

## 推奨

**先に比較実験を回す。** 理由:

- いまの O₂ 軸は「供給在庫が尽きて死ぬ」という**筋の通った失敗モード**を持っており、実際に人が死んでいる。
  基準に照らせないだけで、腕の比較には使える（EXP-011 の追記で O₂ を比較指標に入れた）
- キャビン大気化は**そのシナリオが問う内容を変える**判断であり、チームと合意すべき事柄である
- 比較実験の結果は、論点3（失敗モードを何にするか）を決める材料になる

**この文書をチームへの提案の土台にする**のが良い。乗員4・サバイバル帯分離と合わせて3点。

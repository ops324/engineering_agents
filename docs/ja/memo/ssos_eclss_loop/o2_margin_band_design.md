## 1. 何を変えるか

**B軸「資源余裕」と A軸の O₂ が参照する帯を、減員の段から警報の段へ移す。**

```
いま   plant_sim.survival.bands.o2_storage_low_kg = 91.31 kg   [V2 6003] 軽度低酸素症の下限（死ぬ段）
提案   （新設）運用の帯                          = 104.2492 kg  [V2 6003] 正常酸素域の下端（警報の段）
```

**減員の判定は 91.31 のまま動かさない。** [V2 6003] は 145〜127 mmHg を
"Indefinite with monitoring" としており、帯を出るのは規格違反であって死に方ではない。
`scenario.yaml:105` がそう書いており、その設計は正しい。**変えるのは「余裕」の測り方だけ。**

### なぜ不整合なのか — CO₂ と水は既に警報の段で測っている

```
CO₂   survival.bands 2.0 / 8.0      ==  thresholds 2.0 / 8.0       同じ段
水     survival.bands 50 / 25        ==  thresholds 50 / 25         同じ段
O₂    survival.bands 91.31 / 87.71   !=  thresholds 104.25 / 91.31  **1段ずれている**
```

R2 以前（`cd7a2af`）は3資源とも一致していた（O₂ も 6.0 == 6.0）。
R2（`1d59f49`）が O₂ だけ2段に割り、**`scorecard.py` はその commit に含まれていない。**
`inventory_metrics` は「減員が読む帯」を1つだけ受け取る作りなので、
**O₂ だけが黙って1段下にずれた。**

**ただしこれは「取りこぼし」と断定しない**（EXP-022 の訂正）。
`scenario.yaml` は割ることを意図的だと明記している。
**書かれていないのは「B軸の余裕を、割ったうちのどちらの段から測るか」だけである。**

## 2. 判定基準（これを先に固定する）

**点数の大きさは基準にしない。** 理由は §0 のとおり事後に動かせるため、
そして本件で買えるのは実測 0.02〜0.35点で、**この枝が以前「有意だが小さい」と
記録した +0.246点（EXP-015）より小さい**からである。**点で正当化はできない。**

代わりに、**計器として生きているか**で判定する。4つとも満たすときのみ採用する。

```
基準1 非退化   判断が違う run に違う点を付ける。
               判定: 生存した run の中で、点が2値以上に割れること
基準2 追随     酸素に対して何かした腕と、しなかった腕を分けること。
               判定: OGS 指令が多い群と 0 の群で、並べ替え検定 p < 0.01
基準3 死を報わない  乗員が減るほど点が下がること（EXP-021 が時間項を落とした基準）
基準4 同一を分離しない  軌跡がバイト一致する run に、違う点を付けないこと
                        （EXP-016 が C 軸を落とした基準）
```

**基準1・2 は「提案が満たすか」だけでなく「現状が満たすか」も必ず併記する。**
これが EXP-022 の教訓であり、本文書が存在する理由である。

## 4. 置き場所 — `reference_limits` ではなくリテラルで、拒否側に

前文書は行き先を `reference_limits.o2_kg_for_pio2(145.0, habitat)` としたが、**これは採らない。**

```
                        公表値の容積依存   生存24本の幅   ルール腕−no-op   ガード
現状（91.31）               なし             0.0000          +0.0000       拒否側
reference_limits から取る   **あり**         0.3459          +0.0716       差分対象なし
リテラルで拒否側に置く      なし             0.3459          +0.0716       **拒否側**
```

`reference_limits` から取ると帯がキャビン容積の関数になる。
**容積は共通3軸の 16点全額（A軸CO₂ 8 + B軸CO₂ 8）を支配している**（EXP-022 破れ9）。
いまは `plant_sim.habitat` として拒否側に置いたが、**O₂ の帯までそこに載せる理由がない。**
リテラルなら容積に一切依存せず、分解能は同一である。

### 置き場所の案

```
案A（推奨）  plant_sim.margin_bands.o2_storage_low_kg: 104.2492
             `_scoring_bar_modified` に plant_sim.margin_bands を追加（habitat と同じ扱い）
             意味が正直:「B軸が余裕を測る帯」であって、減員の帯ではない
案B          plant_sim.survival.scoring_bands.o2_storage_low_kg: 104.2492
             既存のガード（survival 部分木の差分）にそのまま載る。追加実装が最小
             ただし survival（減員）の中に減員でない値を置くことになる
```

**おすすめは案A。** `plant_sim.habitat` を拒否側に足したのと同じ手順で足せる（実装済みの前例）。
案B は実装が1行少ないが、**「survival の中身は減員のもの」という読みを壊す。**
ガードを部分木の差分にした理由は「次に増える鍵も自動で覆う」ことなので、
**意味の合わない場所に置いて覆わせるのは、その設計意図の悪用にあたる。**

## 6. 撤回条件（先に書く）

次のいずれかが起きたら、この変更を戻す。

```
撤回1  基準3 が破れる（乗員が減ると点が上がる run が1本でも出る）
撤回2  基準4 が破れる（軌跡が同一の run に違う点が付く）
撤回3  公表比較の符号が変わる（K1 が破れる）
撤回4  「余裕が大きいほど良い」と読めなくなる — たとえば OGS を回さない腕が
       回す腕より高い点を取る集合が見つかる
```

**「点が小さいから戻す」は撤回条件にしない。** §2 のとおり、点の大きさは
最初から採用理由ではないため、それで戻すのは基準の後出しになる。

  故障がいま起きていることは見えてよい。**見えないのは未来である。**
  ⇒ EXP-019 の「引き算1回で分かる」は、**現在**の推定であって**未来**の推定ではない
```

## 提案 — 有限の消耗品吸収剤（LiOH 相当）

**実機の輪郭に合わせる**（ユーザー指示「ARS の異常時は将来的に実機と同じように」）。
一般に、この種の装置は「同じ機体を強く回す」のではなく
**冗長系 / 消耗品 / 代謝負荷の低減**で対処する。ここでは**消耗品**を採る — 最も単純で、
条件 A〜D を構造的に満たすため。

```
新しい状態   consumable_absorbent_kg   初期在庫（有限・補給なし）
新しい指令   use_absorbent {"amount": <kg>}
効果        投入 1 kg あたり co2_removal_per_kg だけキャビン CO₂ を除去。**在庫は戻らない**
```

### 6条件をどう満たすか

```
A 費用      在庫が減る。**補給が無いので、使った分は永久に失われる**
B 別の使い道 故障は run 中に**複数回**起きる。早く使い切ると、次の故障で手当てが無い
C 曖昧さ    ★ **故障が「いま」起きていることは見せてよい。見せないのは「この先」である。**
           継続時間と次の故障までの間隔は seed から決まる（＝run は決定的で再現できる）が、
           観測には出さない。「すぐ戻るなら温存すべき／戻らないなら今使うべき」が事前に分からない。
           **EXP-019 が落ちた「引き算1回で現在が分かる」は、この条件を壊さない**
D 使いすぎの罰 在庫が尽きた後に故障が来ると、手当てゼロで乗員を失う
E 窓        判定は必ず**窓を倍にして**確かめる（EXP-037 の規則）
F 効果の大きさ 吸収剤が乗員を救えるなら、応答の効果は**最大 50点**（残存軸）。
           状況の効果と同オーダーになる ← **これが飽和域の 0.71点を壊す唯一の道**
           ⚠ ただし実測の上限は 50点ではなく **35.91点**（CO₂ で失えるのは乗員4から最大2人）
```

## ★ 監査が申告より重いと判定した弱点（6件・著者は未申告だった）

```
① **配分不変性** — greedy が弱支配的で、未来を知る価値がゼロ（実測 48/48）
② **判定規則①の定数集合に、勝つ定数が入っていない**（事前登録が誤って「成立」を出す）
③ **主指標「共通3軸」は実質「生存者数」** — 400 step の 12 run で A+B の全幅は **0.9634点**。
   判定規則②の「1点以上」は**乗員が1人動かない限り達成不能**。
   設計は「生存者数を主指標にしない」と書きながら、残存 = 12.5×乗員 が 90点中 50点
④ **EXP-028 の撤回条件6「死による節約」が欠落** — 乗員 4→3 で CO₂ 産生が **−25%** に落ち、
   残在庫が 33% 延びる。「**1人見捨てて在庫を延ばす**」が定数政策として立つ
⑤ **seed のホールドアウト／交差検証が無い**（EXP-030 は同じ穴で余地を 11→6 に落とした）
⑥ 撤回条件に「乗員が全滅して差が消える」場合の扱いが無い
```

**条件F の上限も誤りだった: 「最大 50点」→ 実測 35.91点。**
`survival.py` の CO₂ 減員は `alive // divisor` で `_fired` ラッチするため、
**乗員4から CO₂ で失えるのは最大2人**（残存軸で取り返せるのは 25点、A軸を足して 35.91点）。

## ★ 自己申告する弱点（監査官はここを避けて撃つこと）

```
1  **条件C の実装が最も脆い。** 未来を隠すつもりでも、故障の長さが**常に同じ**なら
   1回目の run で学習でき、2回目以降は既知になる。**長さと間隔に分布が要る。**
   そして分布を著者が選ぶ以上、**著者が難易度を作れてしまう**（弱点4 と同根）
2  **条件Fは仮定であって測定ではない。** 「吸収剤が乗員を救える」定格を選べば満たせるが、
   それは**答えを先に決めて定格を逆算する**ことになりかねない。物理的な出典が要る
3  **6条件を満たす設計は、判断が生まれるように作った設計**である。
   「作れば生まれる」のは当たり前で、**面白いかどうかは別**（EXP-025 第1版が落ちた型）
4  複数回の故障は**シナリオの選択**であって物理ではない。頻度と間隔を著者が選ぶ以上、
   **著者が内点を作れてしまう**。頻度は出典か、少なくとも事前登録で固定すること
5  この文書は**実装前の設計であり、S1（定数で解けないか）を実測していない**。
   撤回1 の確認は実装前に行うと書いたが、**吸収剤が無い状態では確認できない**。
   ⇒ **最小実装を先に作り、定数腕を並走させてから本設計に進むのが正しい順序かもしれない**
```

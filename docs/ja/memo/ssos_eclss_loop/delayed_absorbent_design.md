## ★ 遅延の値には出典が無い。だから「幅」で示す

**ROADMAP:311 は「定格・消耗速度は出典を当たってから決めること」と指示している。**
**この枝は実機の吸収剤の応答時間を確認していない。捏造しない。**
代わりに**結論が値に依存しないこと**を測った:

```
遅延(step)  勝率     差の中央値   乗員が動く      物理時間（1 step = 1200 秒）
   0       0/48      0.0       0/48       —
   1       1/48      0.0       0/48       20 分
   2      37/48     28.5       9/48       **40 分**  ← ここから効く
   3      38/48     36.5       9/48       1.0 時間
   5      39/48     38.5       8/48       **1.7 時間** ← 最良
  10      31/48     15.0       5/48       3.3 時間
  20      23/48      0.0       3/48       6.7 時間   ← 中央値ゼロ
```

**⇒ 効果は 40分〜3.3時間 の帯で成立する。** 実機の応答時間がこの帯に入るかは**出典を当ててから判断する**。
**入らなければ、この設計は落とす。**（＝ これも撤回条件である。下記 C6）

## 仕様

```
新しい状態   absorbent_stock_kg        有限・補給なし
            absorbent_pending[]        投入済み・未発効の量（遅延 D step のキュー）
新しい指令   use_absorbent {"amount": <kg>}
効果        投入した量は **D step 後に** co2_removal_per_kg × amount だけキャビン CO₂ を除去。
            在庫は**投入した時点で**減る（発効を待たない ＝ 外したら捨てになる）
故障        ARS 故障の継続時間と間隔は seed から決まる（run は決定的）が、**観測に出さない**
```

## ★ 自己申告する弱点

```
1  **オラクルは真の故障日程を見ている。** 実際の腕は推定しなければならない。
   S1 が示したのは「**先読みに価値がある**」であって「**LLM が取れる**」ではない。
   ⇒ 本測定では「推定できる腕」と「オラクル」の**両方**を並べること
2  **遅延 3 step も 5 step も著者が選んだ。** 帯で示したが、**帯そのものも著者の模型が決めている**
3  **縮約模型は CO₂ だけ。** 水・O₂ の結合が入ると結論が変わりうる
4  **故障の頻度・長さの分布を著者が選ぶ。** 難易度を著者が作れてしまう（第1版の弱点4 と同根）
5  **「判断が生まれるように作った」ことは変わらない。** 作れば生まれるのは当たり前で、
   **面白いかどうかは別**（EXP-025 第1版が落ちた型）。
   ⇒ 主張できるのは「この環境で判断を置ける最小の構造が1つ特定できた」までである
6  **実装は物理の追加＝世代が変わる（v6）。** 公表値が動かないことは C6 で確かめるが、
   **LLM 腕を回した過去の run とは比較できなくなる**
```

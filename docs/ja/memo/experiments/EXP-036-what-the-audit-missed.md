## 問い

**独立監査は、既知の誤りを実際には何件見逃したか。**

記録は「2026-08-29 に7回結論を出し、**7回とも監査が誤りを見つけた**」と書いている。
**これは捕捉の分子だけで、見逃しの分母を一度も測っていない。**

**これは EXP-035 で S2 ゲートを批判したのと同じ欠陥である。**
捕捉率だけを報告し、偽陰性を測らない。**自分の物差しを自分の装置に当てていなかった。**

## なぜ今か（ゴールとの関係）

設計文書のゴールは「ハードウェア要件と変更管理のプロセスを可視化・構造化し、
**エンジニアの協働を効率化する**」である。監査は現在いちばん高い層で、
2026-08-29 だけで **16体**が走り、今日の3体は実時間 826/927/1,272秒を使った
（監査対象の測定そのものは **15秒**）。
**効いているなら払う価値があるが、効いている証拠は分子しかない。**

## 方法 — 記録そのものが答えを持っている

**監査を通してから公開された成果物について、その後に別の過程が見つけた欠陥を数える。**

```
捕捉（分子）  その監査の返答が名指しし、著者が再現した具体的な欠陥
見逃し（分母の一部）
            **監査より後に**見つかった欠陥のうち、
            (i) 監査の時点で既に存在し
            (ii) 監査の時点で入手可能な情報から導け
            (iii) その監査の返答が名指ししなかったもの
資料        git 履歴 ／ EXP 文書の撤回記述 ／ 会話ログの監査ブリーフと返答（18体分が復元可能）
```

### 採点契約（★両側に同じ規則を当てる — 今日新設した規律⑦）

```
捕捉も見逃しも、**「具体的で再現可能な欠陥」でなければ数えない。**
  「懸念がある」「弱いかもしれない」は捕捉にも見逃しにも数えない
  監査が名指しし著者が再現できなかったものは捕捉に数えない（今日1件却下した）
⇒ 「何か問題がある」とだけ言う監査官は、この契約では 0点。判断ゼロの入力は満点を取れない
```

### ★ 何が計算でき、何ができないか（先に書く）

```
計算できる    後から**見つかった**見逃し → 見逃し数の**下限**
計算できない  まだ誰も気づいていない見逃し → 永久に不明
⇒ 出るのは「捕捉率の**上限**」であって捕捉率ではない。
   **「7/7」を「上限 x%」に置き換えるのが本実験の成果であり、真値は出ない**
```

## ⇒ 「7回中7回」の正確な意味

**「ブリーフがスコープに入れた文書の中の誤りを、7回中7回捕まえた」。**
**スコープの外は数えていない。そして測れた失敗は、3つとも全部スコープの外にあった。**

## ゴールに対する含意

```
強い   渡された文書の**中**では強い。今日も著者の主要結論2つを覆した。
      公開前に監査を通した5件に、後から見つかった欠陥は無い（ただし観測窓は数時間）
弱い   ①**置き換えの主張**（監査が出した新しい結論が、測定として扱われない）
      ②**スコープの決め方**（波及先が誰のスコープにも入らない）
⇒ **どちらも監査官の能力ではなく、ブリーフを書く側＝著者の責任である。**
   **監査官を増やしても直らない。**
```

## この測定から出た具体的な改善（3件）

```
1  **監査が「置き換えの結論」を出したら、それを測定として扱う。**
   採用する前に、その結論自体を S3（事前登録）→ S4（測定）に戻す。
   EXP-029 はそれをせず、監査返答の8分後に公開して 88分で撤回になった
2  **毎回1体は「この変更が古くする文書」をスコープにする。**
   層4（`stale_sweep.py`）の自動化ではなく、**ブリーフの必須項目**として。
   7時間14分・8体という数字は、これが無いことの直接の費用である
3  **再現しない指摘の率を記録し続ける**（今日 1/3）。監査を信じる度合いの根拠になる
```

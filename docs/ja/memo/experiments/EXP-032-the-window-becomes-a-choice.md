## 何をしたか

`simulation.steps` を **50 → 72** にした。`step_seconds` は 1200 のままなので、
**72 × 1200 秒 = ちょうど 24 時間 = 1日**である。

**これはこの枝の選択であって、チームの基準ではない。**
上流も土台も 50 で、この枝も v3 / v4 / v5 を通じて 50 で走ってきた。

## なぜ変えたか

### 50 は誰も選んでいなかった（git 履歴・実測）

```
2026-06-26  steps: 8
2026-08-16  steps: 40
2026-08-19  steps: 50   # decision cycles (observe → deliberate → act)
            ← PR #53「Scale ssos_eclss_loop operator team and **fit vLLM prompts**」
              **この時点で step_seconds は存在しない。** 50 は「エージェントが何回考えるか」の回数
2026-08-22  step_seconds: 1200 を別の PR #54 で追加（マージ日）
2026-08-22  steps: 50   # default observation steps  ← 注釈だけ書き換え
```

**「16.7 時間」は、別々の PR で、別々の理由で決められた2つの数の積である。**
どちらのコミットメッセージにも値の根拠は無い。**誰も持続時間を選んでいない。**

**⚠ 訂正（監査）: 「3日違い」はマージ日の差である。** `step_seconds: 1200` を書いた作業 commit の
author date は #53 のマージの **2分後**で、同じチームが同じ晩に並行で書いている。
そして**その commit は同時に `steps` を 40 に戻している** — 1200 を書いた人は「40×1200 = 13.3時間」の
世界にいた。**16.7時間は2つの PR が合流したときに初めて生まれた数**で、やはり誰も書いていない。
本質は変わらないが、「無関係な2人」を演出しすぎだった。

### そして 50 は、いちばん不安定な場所に座っていた（[EXP-031](EXP-031-the-second-headline-was-the-window.md)）

既存 run を窓 W で切り直すと（追加 run ゼロ）:

```
W 16〜20   LLM 腕が no-op より**有意に良い**
W 28〜34   全腕が同じ値 ＝ **交差点**
W 36〜50   LLM 腕が後ろ、ただし有意でない

W=50 での LLM vs no-op の p:  v3 0.050 / v4 0.049 / v5 0.170
→ **3世代のうち2つが有意の境界線上。** 最も揺れやすい場所である
```

### 72 を選んだ理由

```
① 文章で言える候補         「**1日ぶんの生命維持を保てるか**」。16.7時間には対応する言葉が無い
   **⚠ 訂正（監査）: 「唯一」は誤り。** 144（2日・GPU 9.5時間）と 216（3日・14.3時間）も
   同じくらい言える。著者は「4.9時間は現実的／34時間は払えない」と書きながら、
   **その間を一度も検討していない。実際の決め手は費用であって、言えるかどうかではなかった**
② 交差点から離れている       36（半日）は交差点の 2 step 隣で、答えが刃の上に乗る
   **⚠ 限定（監査）: 「38 step」は v5 基準。** 交差点は世代で動く（v4 は 27〜28、v3 は 42〜44）。
   **v3 基準なら余裕は 28 step。** どの世代でも交差点から離れている W≤50 の値は存在しない
③ 費用が現実的            LLM 24本で GPU 約4.9時間（現行 3.5時間）。
                        504（1週間）は分離が最も明確（no-op が 0/4）だが 34時間で払えない
④ 「続けられるか」を測る側   EXP-031 の発見は「**LLM 腕は早く撃ち、続かない**」。
                        生命維持では続けることのほうが重い。短い窓は「早い」を、長い窓は「続く」を測る
```

## ★ 監査が見つけた、窓より重い交絡 — `request_o2`

**著者が再現した（v5・24本の LLM run を `request_o2` の使用有無で分ける）:**

```
W=50   使わなかった 20本 → 生存 全部 3・**分散ちょうど 0**（no-op と完全に同一）
       使った 4本       → 生存 1, 3, 0, 3（平均 1.750）
```

**「LLM は no-op と区別できない」の実体は、24本中20本が no-op と1人単位で同じ結果だということ**である。
`request_o2` はキャビンの O2 を抜く指令で、1回 3〜7 kg。それを使った4本だけが下に外れている。

**ただし監査の「窓を直しても直らない」は言い過ぎで、著者の再現では窓と交絡は別の現象だった:**

```
        request_o2 なし群 vs no-op（生存者数）
   W     v3            v4            v5
  15   3.700 (分散あり) 3.444 (分散あり) 3.600 (分散あり)   ← **交絡抜きでも LLM が上**
  50   2.750           3.000          3.000 **分散0＝完全同一**
```

**⇒ 短い窓での「LLM が良い」は交絡ではなく本物。長い窓での「LLM が悪い」は交絡が作っている。**
機構: **LLM は早く撃って全体に効き、そのあと何もしなくなる（no-op に収束）か、`request_o2` で自傷する。**

**これは EXP-031 の窓の発見を否定しない。両方が正しい。**
そして**次に測るときは `request_o2` で層別する**こと。窓の位置を直しても、この4本の重みが変わるだけである。

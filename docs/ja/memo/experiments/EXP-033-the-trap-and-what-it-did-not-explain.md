## ★ 機構 — `request_o2` は純粋なシンクである（コードから確認）

```python
def request_o2(self, amount_kg: float) -> float:
    granted = min(s.cabin_o2_kg, amount_kg)
    s.cabin_o2_kg -= granted            # キャビンから抜く
    s.total_o2_delivered_kg += granted  # 集計欄に積むだけ
```

`total_o2_delivered_kg` は `physics_gate` が**損失**として扱う（`lost = consumed + delivered`）。
**抜いた酸素はどこにも行かない。**

```
プロンプト   persona.py:200 が LLM に明示的に提示している
ルール腕     `_labeled_recovery` に **request_o2 の分岐がコードに存在しない**。
            「観測上0回」ではなく**構造上出せない**（実測でもルール腕5本すべて0件）
採点        専用の扱いは無い。ただし **成功した request_o2 は C 軸の invalid_ops で
            わずかに加点される**（applied に数えられる）。D 軸は details が無いのでスキップ。
            正味では A・B で失う分がはるかに大きい
```

### ★★「rejected」と記録された指令でも、酸素は抜ける

```

  success=False  response_value=8.6083   ← 在庫 8.643 kg のほぼ全部が抜けた
```

`plant_sim/backend.py` の `_request` は **`granted = payout(amount)` を無条件に実行**してから
`success` を判定する。**一方 `loop_mock_backend.py:132` は
"All-or-nothing like SSOS `/ogs/request_o2`: reject without mutating" と書いている。**
**mock と plant_sim で契約が食い違っている。** これは実バグでチームに諮る価値がある。

**含意: 「backend で拒否する」という対策は、現行の実装では効かない。**

## ★ 用量反応はある。ただし閾値は「kg」ではなく「帯を割ったか」

初稿は「約 5 kg を境に」と書いた。**誤り。** v3/v4 は O2 が **8 kg のタンク**、
v5 は **104.86 kg のキャビン**で、同じ 5.0 kg が v3 では在庫の 62.5%、v5 では 4.8% になる。
**同じ 5.0 kg が、v3 llm_r21 では4人死に、v5 llm_r20 では0人である。**

**正しい機構は「致死帯を割るまで抜いたか」である:**

```
v5 llm_r20  step31 o2=103.869 → -5.00 → 98.834（警告帯 91.31 の**上**）→ **死者0**
v5 llm_r23  step31 o2=104.172 → -15.00 → 89.196（91.31 の**下**）→ step35/37/39 に **3人死亡**
v5 llm_r15  step45〜49 で -20.00 → **82.982**（絶対床 87.71 の下）→ step49 に o2_critical 2人
```

**要求量ではなく実際に抜けた量（granted）で見ること。** 在庫より多く要求すると
requested と granted がずれる（v3 llm_r20 12.0→9.567 / llm_r12 10.0→8.608 /
v4 llm_r4 8.0→6.950 / llm_r8 7.5→7.149）。

```
使用 **13本** → O2 死 27人（2.08/本）
未使用 59本  → O2 死 14人（0.24/本）    **8.8倍**
うち v5 の未使用20本の O2 死は **ゼロ**
```

**v3/v4 の未使用群に O2 死があるのは世代差である** — v3/v4 は O2 が 8 kg のタンクで
代謝でも枯れた。v5 はキャビン大気 104.86 kg で、代謝は 50 step で 1.75 kg しか減らせず
警告帯まで 13.55 kg あるので届かない。**v5 では `request_o2` が O2 死の唯一の原因である。**

## ★ 罠を除くと、LLM 腕は no-op に勝つ（初稿の逆）

**v5・request_o2 未使用20本 対 no-op（1標本 t 検定）:**

```
指標                    no-op      未使用20本        差        p
W=50 生存者             3.000    3.000 ±0.000    0.000    分散0   ← **唯一の同一**
person-steps          164.000  166.300 ±3.389   +2.300  0.006809  ★勝つ
初回死亡 step           14.000   16.300 ±3.389   +2.300  0.006809  ★勝つ
peak CO2 (小さいほど良)   3.630    3.163 ±0.438   -0.466  0.000135  ★勝つ
min O2 (大きいほど良)   102.982  103.514 ±0.567   +0.532  0.000486  ★勝つ
min 水位                74.902   74.822 ±1.777   -0.079  0.843978    同等
```

**生存者数だけが同じで、勝ちは「死を遅らせた分」に現れる。**
生存者数は 0〜4 の5段階しか取らない粗い指標で、**差を丸め落とすことは既に分かっていた**
（EXP-016・記憶「person-steps にだけ分解能」）。
**初稿はその潰れた数を根拠に「同一」と断言した。** 文書の末尾で自分が
「生存者数は両方を1つの数に潰している」と書いていながらである。

**そして「v4 も完全に同じ」も誤り。** v4 の未使用18本は **{2:1, 3:16, 4:1}・sd=0.343** で、
平均が偶然 3.000 になっただけである（v5 だけが真に分散0）。


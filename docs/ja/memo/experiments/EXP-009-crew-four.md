## 変更の理由

trunk の運用点（乗員50）は、**選ばれた難易度設定ではなく噛み合っていない状態**だった（EXP-007）。

```
ARS 4.50 kg CO2/day ÷ 1.04 kg/人/day = 4.33 人分   ← 装置は4人用
OGS 9.25 kg O2/day  ÷ 0.84 kg/人/day = 11.0 人分
容積 388 m³ ÷ 4人 = 97 m³/人（ISS は 388 m³ に6人 ≒ 65 m³/人）
```

**`scenario.yaml` の CO₂ 除去装置は定格が 4.33 人分**で、そこに50人を入れていた。結果は 48/48 の全滅で、
どの腕も区別できなかった。人数を装置と容積に合わせる。

**代案 B（装置と容積を50人に合わせる: ARS 約52 kg/day、容積 約3,200 m³）は採らない。** 変更範囲が大きく、
「ISS の12倍規模」という根拠を別途要する。

## 予測（結果を見る前に記録）

1 step = 1200 s、乗員4人での計算:

```
CO2 生成   4 × 1.04 × 1200/86400 = 0.0578 kg/step
O2 消費    4 × 0.84 × 1200/86400 = 0.0467 kg/step
水消費     4 × 2.28 × 1200/86400 = 0.1267 L/step
ARS 1回    0.25 kg   = CO2 生成 4.33 step 分
OGS 1回    0.1285 kg = O2 消費 2.75 step 分
```

| # | 予測 | 根拠 |
|---|---|---|
| P1 | `none` 腕は乗員を失うが**全滅しない**（残存 1〜3） | ARS 無しで CO2 は step 12 に 2.0 kg を越え帯に居座る → `n//4` = 1名。O2 は step 43 に 6.0 kg を割り WARNING 反復 |
| P2 | `labeled_rule_base` 腕（故障なし）は**乗員4を維持**（損失ゼロ） | ARS 1回で 4.33 step 分を除去でき、2 step 連続 WARNING に至らない。OGS も同様 |
| P3 | 故障注入ありのルール腕は**乗員を失う**（1〜2名） | ARS 停止 step 10–20 の間に CO2 が帯に居座る |
| P4 | CO2 CRITICAL (8.0 kg) にも O2 CRITICAL (1.0 kg) にも**到達しない** | ARS 皆無でも 50 step で 1.3 + 2.89 = 4.19 kg。O2 は 5.67 kg 残 |
| P5 | 水は**不動**（50 L を割らない） | 消費 0.127 L/step、初期 80 L、WRS 回収あり |
| P6 | peak ppCO₂ は **3 mmHg を跨ぐ帯**に入る（none 腕 約4.5、ルール腕 約2.2 mmHg） | 388 m³ で 4.19 kg = 4.5 mmHg、2.0 kg = 2.15 mmHg |

**P2 と P3 が両方当たれば、シナリオは「操作の良し悪し」と「故障の影響」を区別できる。**
P2 が外れて誰も死なない場合は v1 と同じ「易しすぎ」に戻ったことになり、難易度は故障注入で上げる。

labeled_rule_base 故障なし     4     0        200      2.053    2.21       0      0.00

### 予測の答え合わせ

| # | 予測 | 実測 | |
|---|---|---|---|
| P1 | `none` は損失ありだが全滅しない（残存1〜3） | 残存 **3**、損失1 | ✓ |
| P2 | ルール腕（故障なし）は乗員4を維持 | **4、損失0** | ✓ |
| P3 | ルール腕（故障あり）は1〜2名を失う | **1名** | ✓ |
| P4 | CO2 CRITICAL(8.0) / O2 CRITICAL(1.0) に到達しない | peak 3.63 kg / min O2 5.97 kg | ✓ |
| P5 | 水は 50 L を割らない | min **74.90 L** | ✓ |
| P6 | peak ppCO₂ が 3 mmHg を跨ぐ帯に入る（none 約4.5 / ルール約2.2） | 跨いだ（none 3.91 / ルール 2.21）。**ただし none の値は予測より 0.6 mmHg 低い** | △ |

**P6 のずれの理由**: 予測は乗員4人が50 step 続く前提で 4.19 kg を計算したが、実際は step 14 で1名失われ、
以降 CO2 生成が 3/4 に落ちた。**減員が負荷を下げるという負のフィードバックを予測に織り込んでいなかった。**

### 判別できるようになったこと

- **運用者の有無**: ppCO₂ が分ける。ルール腕 0 step 超過 / no-op 腕 20 step 超過（exposure 8.62）
- **故障の代償**: 乗員が分ける。ルール腕 200 → 164 person-steps、残存 4 → 3

**この2つは別の指標が担当する。** ppCO₂ はルール腕の故障あり/なしを区別しない（両方 0 step 超過）。
乗員数は no-op 腕の故障あり/なしを区別しない（両方 164）。**片方だけでは足りない。**

### 予測していなかった観察

- **`inject_failures` は `none` 腕で完全に無効**（4値すべて一致）。v2 と同じ。故障注入は環境の摂動ではなく
  「運用者を無効化するレバー」なので、運用者がいなければ何も起きない
- **O2 と水は依然としてほぼ不動**。min O2 5.97 kg（CRITICAL は 1.0）、min 水 74.90 L（LOW は 50）。
  **今回の判別は CO2 の1軸から来ている。** v1 の「実質 CO₂ の1軸問題」は乗員4では再現する
- ルール腕の peak 2.053 kg は `co2_high` 2.0 のすぐ上。ARS が閾値で発火して押し戻している

## 副作用（2026-08-26 追記）— スコアカード主軸の分解能が落ちた

`20260823_ECLSS_SIM_評価・検証スコアカード案` の主軸は **50 × 残存 ÷ 初期** である。
乗員数を下げると、この軸の取りうる段階数がそのまま減る。

```
乗員  4 →  5 段階、1人あたり 12.5 点   ← 現在
乗員 10 → 11 段階、1人あたり  5.0 点
乗員 50 → 51 段階、1人あたり  1.0 点   ← チームの設定
```

ゲート合格の LLM run 21 本での実測:

```
残存 0人  0.0点  ■
残存 1人 12.5点  ■■
残存 2人 25.0点  ■■
残存 3人 37.5点  ■■■■■■■■■■■■■■■   ← 21本中15本
残存 4人 50.0点  ■

                  CV      必要n/arm   GPU時間/arm
crew_remaining   35.2%     198本      26.4時間
person-steps     10.5%      18本       2.4時間
```

さらに主軸は**死んだ時刻を捨てる**。残存3人（すべて 37.5 点）の15本の person-steps は
164〜195 に散っており、「早く1人失った run」と「終盤まで4人保った run」が同じ点数になる。

**これは主軸の欠陥ではない。** スコアカードは A軸（帯滞在step数・最長critical連続）と B軸で
その情報を拾う設計になっている。**50点軸だけで腕を比較する使い方が誤り**である。

ただし**乗員4はこの副作用を持つ**ことは記録しておく。装置定格との整合と引き換えに、
主軸の分解能を 1/10 にした。チームへ確認すべき点が一つ増えた:

> 乗員4では主軸で腕を比較するのに 26時間/条件かかる。A軸に生存の積分を加えるか、
> 乗員数を上げるか、どちらかの判断が要る。

## 結論

**乗員4はシナリオに判別分解能を与える。** 予測6件中5件が的中し、外れた1件は減員の負のフィードバックという
機構の見落としだった（数値の方向は正しい）。

ただし判別は **CO₂ 軸だけ**から来ている。O2 と水を評価に組み込むなら、次はタンク初期値か閾値の側を
見直す必要がある（どちらも実験条件なので人間の判断）。

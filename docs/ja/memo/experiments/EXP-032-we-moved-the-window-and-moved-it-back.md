## 何をして、なぜ戻したか

[EXP-031](EXP-031-the-second-headline-was-the-window.md) で、公表結論の片方が
**観測窓 50 を選んだことの産物**だと分かった。50 には根拠が無い。
そこで **72 step（＝ちょうど24時間）に変更した。** 独立監査を通し、**戻した。**

**戻した理由は1つ。72 は分解能を1ミリも増やさなかった。**

```
steps   実時間    ルール腕   no-op   差
   20    6.7h       4        3     1
   36   12.0h       4        3     1
   50   16.7h       4        3     1   ← 現行
   72   24.0h       4        3     1   ← 変更しようとした値
  144   48.0h       4        3     1
  200   66.7h       4        2     2   ← ここで初めて変わる
```

**乗員の分解能は step 14〜150 の全域で「4 対 3」のまま。**
50 と 72 は判別力が完全に同じである。

```
72 が買ったもの   「1日」と言える文章 1つ
72 が払うもの     ・3世代ぶんの LLM 測定 72本が比較不能になる
                 ・v6 で AI の答えを得るのに GPU 4.8時間
                 ・上流との分岐
                 ・**分解能の向上はゼロ**
```

**割に合わない。** 200 step 以上なら分解能は本当に増えるが、GPU 14.3時間/世代である。

## ★ 著者の判断ミス

**72 を選ぶとき、「交差点から離れているか」と「費用」は調べたが、
「そもそも分解能が増えるのか」を調べなかった。** 監査が指摘し、測ったら増えていなかった。

**「50 に根拠が無い」は正しい発見だった。だが根拠が無いことの正しい対処は
「別の数に変える」ではなく「根拠が無いと書く」である。**
72 も LLM 腕については未検証の数であり、**根拠のなさは 50 と同じだった。**

## 残したもの（これが本当の成果）

### ① `scenario.yaml` に「この値に根拠は無い」と全文で書いた

由来（PR #53 の「思考回数」／`step_seconds` は当時存在せず、別 PR #54 で2分後）、
EXP-031 の窓依存、72 を試して戻した経緯、そして下の規律。**消すのではなく書く。**

### ② 規律 — **窓を1点だけ報告しない。曲線を併記する**

**すべての run は `events.jsonl` に各乗員を失った step を持つ。**
したがって**その run の窓以下なら、追加 run ゼロで切り直せる。**
**結論が窓で動くなら、そう書く。** これが EXP-031 の問題への正しい対処である
（別の1点に移しても、依存は見えないままになる）。

### ③ ★ 窓より重い交絡を見つけた — `request_o2`

```
v5・W=50  request_o2 を使わなかった 20本 → 生存 全部3・**分散ちょうど 0**（no-op と完全同一）
          使った 4本                    → 生存 1,3,0,3（平均 1.750）
```

**「LLM は no-op と区別できない」の実体は、24本中20本が no-op と1人単位で同じ結果だということ。**
`request_o2` はキャビン O2 を抜く指令で、1回 3〜7 kg。

**ただし窓の発見と交絡は別の現象で、両方が正しい:**

```
        request_o2 なし群 vs no-op（生存者数）
   W     v3            v4            v5
  15   3.700 (分散あり) 3.444 (分散あり) 3.600 (分散あり)   ← **交絡抜きでも LLM が上**
  50   2.750           3.000          3.000 **分散0＝完全同一**
```

**⇒ 早く撃つ利点は本物。長い窓での劣位は交絡が作る。**
機構は「**LLM は早く撃って全体に効き、そのあと何もしなくなるか `request_o2` で自傷する**」。
**次に測るときは `request_o2` で層別する。窓の位置を直しても、この4本の重みが変わるだけである。**

### ④ 窓に依存する記述を洗い出した

```

                              → 72 の間だけ偽だった。**既定に依存する根拠は既定が動く日に腐る**
                                という注記を残した
docs/ja/cli.md / index.md      手順書の `--steps 50` 4箇所 → **削除した**（既定に任せる。
                              シナリオが決めている値を手順書が二重に固定する必要は無い）
agents.yaml の co2_recovery_margin  「50 step では広くしても変わらない」
                              → **この論法は窓依存である**と明記した
```

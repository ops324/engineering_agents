## ★★ しかし余地は1ビットに縮む — EXP-026/EXP-030 の失格基準


**⇒ この運用点で「状況に応じて変える」ことの中身は、
`初期O2 が低ければ電気分解に回す水を増やす` という閾値1本である。**
**t=0 に一度見て、2つの定数のどちらかを選ぶだけ。以後は考えない。**

**これは EXP-026 の失格基準（判断ゼロの入力が満点を取る）と
EXP-030 の失格基準（余地の全部が1ビットで取れる）に、そのまま該当する。**

## seed は効かない（確かめた）

seed 101 / 102 / 103 で**完全に同一**（単一定数の合計 1126.74 が3本とも一致）。

サンプリングされない。ルール腕も決定的。**だから seed は結果を動かさない。**

## ★ 著者が自分のデータを1度壊した（検出の経緯を残す）

```

           **既定値は seed 101 の run が入っているディレクトリで、黙って上書きされた**

直した     `constant_s101/` に作り直し（決定的・70秒）、壊れた側は
           `constant_CONTAMINATED_seed103/` に隔離して README で使用禁止と明記
教訓       **出力先を引数の既定値にしたスクリプトを、引数を空にして呼ばない。**
           そして**「都合よく綺麗な結果」は、まず計器を疑う入口である**
```

## 判定

**案3 の S1 は落ちた（4回目）。ただし今回は落ち方が違う。**

過去3回は「内点が無い／定数が全部取る／打ち切りの産物」だった。
**今回は内点があり、定数は全部を取れず、汎化する余地が正の値で出た。**
それでも**その余地は1ビットで、t=0 の一度きりの選択に縮む。**

**判断を置く場所は、まだ無い。**

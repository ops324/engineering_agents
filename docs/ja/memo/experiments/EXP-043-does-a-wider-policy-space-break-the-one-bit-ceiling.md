## 問い

**政策空間を 12 → 144 通り、状況を 16 → 32 セルに広げても、汎化する余地は1ビットのままか。**

EXP-042 の限界⑥がそのまま問いになる。**EXP-030 は「1キーに絞ったのが誤りだった」と言った。
EXP-042 は3キーだった。それでも狭いかもしれない。**

```
広げても1ビットのまま     → **強い否定。** この運用点に判断は置けないと、初めて正面から言える
2ビット以上が交差検証で勝つ → **初めて判断の置き場所が見つかった**ことになる
```

**どちらに転んでも結論が出る。** それがこの実験を回す理由である。

## ★★★★ そして構造が1つの式になった — **窓に依存しない締め方は存在しない**

崖の位置を3つの窓で測った（21 run・GPU 0秒）:

```
        崖の実測（乗員 4/4 になる初期水）   50 + 0.032 × 窓
 窓 200        56.0 〜 56.75 L                56.4 L
 窓 400        60.0 〜 65.0  L                62.8 L
 窓 800        75.0 〜 80.0  L                75.6 L
⇒ **崖の位置は窓に対して線形。** 3点とも予測が実測の括弧に入る

機構: 水はほぼ一定速度（約 0.032 L/step）で減り、**政策が変えられる幅は小さい**
  同じ状況で政策144通りの最終水の幅  **3.445 L**（200 step。基礎排水 6.4 L に対して）
  そのうち**生存した27政策の最終水は 49.882〜50.608 L** ＝ 全部が帯 50.0 L の縁に張り付く
```

**⇒ 案3 の原文は「運用点を締め、O₂ と水が**窓内で**帯に届くようにする」だった。**
**「窓内で届く」は窓を固定しないと定義できず、窓を倍にすれば同じ点は必ず崖の下側に来る。**

**これは案3 の4回目の失敗ではない。案3 が、この物理の下では定義できない理由である。**
排水が一定速度である限り、締め方は「その窓のための締め方」にしかならない。

## ★ 決定打 — O₂ と水を**同時に**締めると、政策ノブ1本に両端が壊滅する内点が出る

EXP-028 が変えたのは `simulation.initial_product_water_l` だけだった。
**`simulation.initial_o2_storage_kg` を一緒に締めていない。**

```
初期O2 92.0 kg ＋ 初期水 52.0 L・agents.actor.policy.ogs_goal.input_water_mass を振る
要求量   生存   最小O2 kg   最小水位 L   死因
0.000     0     91.113     51.319    o2_warning ×4    ← 回さないと O2 で全滅
0.040     4     91.454     49.872    —
0.075     4     91.359     49.909    —
0.110     4     91.323     49.917    —
0.150     0     91.839     49.774    water_warning ×4 ← 回しすぎると水で全滅
1.000     0     91.839     49.774    water_warning ×4
scoring_bar_modified = []           ← 物差しは1ミリも動いていない
```

**両端が壊滅し、中央が満点。** 機構は実装の副作用ではなく**物理**である —
`run_ogs` は可飲水を電気分解して O₂ を作る。回さなければ O₂ で死に、回しすぎれば水で死ぬ。

**これは案3 が約束していたものそのものである。** 案3 の原文（EXP-017 の希少性3）は
「運用点を締め、**O₂ と水が**窓内で帯に届くようにする」だった。
EXP-028 は水だけを締め、O₂ 側を一度も測らずに案3 全体を否定した。

**⚠ 正直に書く: 内点の中は滑らかな山ではない。** 0.060 → 生存0、0.090 → 生存1 と**櫛状**である。
乗員4は生存窓が狭く脆い。乗員を増やすと（監査官の測定）窓は広く頑健になる。
**「内点がある」と「そこに安定して到達できる」は別の問題で、後者は未解決である。**

## EXP-028 の誤り（すべて著者が再現した）

### 誤り1 ★「ARS に水のコストが無い＝結合していない」は、飽和領域だけで測っていた

EXP-028 の「決定打」は「乗員4固定で ARS 指令を 50→37 にしても水位が 78.1632 で
小数4桁まで同一」だった。**この表自体は正しい。だが範囲が飽和の中に収まっていた。**

```
乗員4固定（CO2 減耗を無効化）で co2_high を飽和の外まで広げる
co2_high    最終水位 L
  0.5      78.163192
  2.0      78.163192   ← EXP-028 はここまでしか見ていない
  4.0      77.265353
1000.0     77.150552   ← ARS 全停止
差（既定 2.0 と全停止）= 1.012641 L
```

**ARS は Sabatier 経由で水を「作って」いる。50 step あたり 1.012641 L。**
これは EXP-028 が「内点の全幅」と呼んだ死1人分 0.4833 L の **2.1倍**である。

**著者は自分の事前登録の撤回条件3 を発火させ損ねた:**

> 撤回3 飽和して全 trigger が同一値になった場合、「最適が下端」ではなく「**測れていない**」。
> 内点が無いことの証拠にしてはならない（EXP-027 の 1.0 と 0.5 が同一だった型）

**まさにその型だった。** 符号は協働（ARS を回すほど水が増える）なので
「CO₂ 軸に代償は無い」という判断自体は残るが、「**結合が無い**」「**経路は乗員の死1本だけ**」は偽である。

### 誤り2 ★「在庫と速度を両方締めると内点が 1/8 → 0/8 に減る」は格子の産物

EXP-028 の掃引8 は水位を **1 L 刻み**で振った。**内点の窓は 0.5〜0.8 L しかない。**

```
             EXP-028（1 L 格子）      再測定（0.1〜0.2 L 格子）
漏れ 0.03    内点 2点・窓 0.5 L    →  窓 約0.5 L   （一致）
漏れ 1.0     内点 1/8 セル         →  窓 約0.8 L
漏れ 2.0     内点 **0/8 セル**     →  窓 約0.8 L   ← ゼロではない
```

**内点は消えていない。漏れを強めるほど 0.5 → 0.8 L に広がる。**
EXP-028 はこの偽の結果の上に「崖と崖」「測度ゼロ」「勾配の綱引きではない」という
構造的な物語を載せていた。**その物語は支えを失う。**
著者自身の論法に従えば「漏れを増やすと内点が広がる」は**案3 を支持する**証拠である。

### 誤り3 「窓の中は同点で既定値 2.0 が最適＝何もしないのが最適」は偽

細格子では、**既定値 2.0 が厳密に負ける行がある:**

```
漏れ 0.03・初期水 51.7 L :  co2_high=1.5 → 生存2   既定値 2.0 → 生存1
漏れ 1.0 ・初期水 53.0 L :  co2_high=1.5 → 生存1   既定値 2.0 → 生存0
```

### 誤り4 「ループが閉じている／窓を延ばしても帯に近づかない」は自分のデータに反する

監査（VERIFY）が p10 の 400 step 全軌跡を 50 step 窓ごとに最小二乗で取った:
**step 100 以降、水の傾きは −0.0316 L/step でほぼ完全に一定。漸近の兆候は無い。**
平衡ではなく**一定速度の排水**である。正しい記述は「ループが閉じている」ではなく
「**排水が観測窓より19倍遅い**」。950 step という有限の値を自分で出しておきながら
地の文が「届かない」と書いているのは内部矛盾だった。

**O₂ の 2230 step も過小評価。** 立ち上がりの過渡（400 step の低下の43%が最初の50 step）を
含む全区間平均で外挿していた。漸近区間（200〜400 step）で引き直すと **約 3330 step**。

### 誤り5 「既存パラメータでは帯に到達不能＝R4 は新しい項でなければならない」は偽

```
plant_sim.crew.activity_factor だけを変える（他は既定・故障あり）
af    生存   最小水位 L   死因

10.0    0     48.771    co2_warning, co2_critical, **water_warning ×2**

```

**既存の代謝パラメータ1本で水の帯に届き、水で2人死ぬ。**
監査（BREAK）はさらに、質量保存を保ったまま**全項を比例スケール**すれば
（`potable 13.68 / urine 9.0 / condensate 4.5 / unrecoverable 0.18` ＝ BVAD ×6）
最小水位 50.64 L に届くことを示した。**「リサイクル全廃が漏れの上限」も偽。**
上限を決めているのは回収率ではなく**乗員スループット**で、それは既存の定数である。

**⇒ R4 に渡した「漏れは代謝に紐づかない新しい項でなければならない」は撤回する。**
倍率の見積り（水 4.7倍・O₂ 5.8倍）自体は正しいが、それは既存定数の掛け算で実現できる。

### 誤り6 事前登録の自己採点が事実と違う

**⇒「事前登録が3回連続で仕事をした」は撤回する。2回である。**

## 何を監査にかけたか

前セッションが推奨した「O₂ の帯を `reference_limits` から取り直す」を**却下する**という設計文書
（[o2_band_and_habitat_design.md](../ssos_eclss_loop/o2_band_and_habitat_design.md)）。

**発動条件は原則4 の主条件に加えて、もう1つあった** — この結論は**却下**であり、
**却下は著者にとって作業が減るという利得がある。** 3体すべてにその構造を明示して渡した。

**結果: 中心の数字が誤っていた。誤りの向きは却下に有利だった。**

# 第1部 — 自分の設計文書を撤回する

## 撤回1: 「生存24本の幅 0.075点」は **0.346点**（4.6倍）

却下の根拠として文書が3箇所で引用していた数字である。**`llm_r20` が集計から落ちていた。**

```
生存 (crew>=3) n=24
  現行の帯 91.31     6.0000 .. 6.0000   幅 0.0000   異なる値  1
  提案の帯 104.25    5.6541 .. 6.0000   幅 0.3459   異なる値 16
  下端の run: llm_r20（crew 3/4, min_o2 98.239 kg）
  llm_r20 を外すと 5.9250 .. 6.0000 = 0.0750  ← 文書の数字が再現する
```

原因は集計を OGS 指令数でグループ表示させたまま目視で下端を読んだことで、
`llm_r20` は `OGS=3` のグループの範囲（5.1788..5.9486）の内側に隠れていた。

**落ちた run は、提案が拾おうとしていた当のケースである。**
`llm_r20` は乗員 3/4 で生存しながら酸素軌道だけが壊滅的で、提案の帯での不足積分は
**101.77（no-op 23.58 の4.3倍）で全 run 最悪**。3体のうち2体が独立にこれを指摘した。

## 撤回2: 同じ検定を現状の帯に当てていなかった

文書は「生存者の中で分離するか」を却下の決め手にした。**現行の帯には当てていない。**

```
                    生存24本      OGS>=11(n=10) vs OGS=0(n=6)
現行の帯 91.31      幅 0.0000     差 0.0000   検定が成立しない
提案の帯 104.25     幅 0.3459     差 +0.0630  Welch t=12.23  並べ替え p=0.00010（20万回）
生存24本での順位相関（OGS指令数 と B軸O₂）  Spearman +0.7643
```

**現行の帯は、著者自身が持ち出した合格基準を 0.0000 で落ちる。**

## 撤回3: 反例に選んだ run が、同類3本のうち都合の良い1本だった

```
run       OGS指令  request_o2  B軸O₂(提案)  ref_none 比
llm_r9       47        1         5.9478      +0.0208   ← 文書が挙げた唯一の run
llm_r4       45        0         5.9974      +0.0704

```

**`llm_r9` が低いのは軸が酸素管理を向いていないからではなく、その腕が自分でキャビンから
O₂ を抜いたから**（EXP-014 が記録した `request_o2` の自傷）。軸は正しく罰している。

## それでも「`reference_limits` に移さない」は残る。ただし理由が入れ替わる

「破る」監査が全経路で帯 91.31 を動かそうと試み、**すべて失敗した**
（`--set` / `--override-file` / `--apply-proposals` / `graph_rewire` / pristine 差し替え）。
`653acdf` の部分木差分は帯に対して実際に効いている。

そして**移し先の危険が、文書の見積もりより桁違いに大きい:**

```
容積指定だけで動く点数（共通3軸/90・全26 run）
  振れ幅               15.996 〜 15.998点   ← A軸CO₂ 8点 + B軸CO₂ 8点 の全額
  正直な 388 からの利得  最大 +8.12点
文書の「11.15点」は 100 m³ と 3000 m³ の差で、100 m³ は正直な申告より損をする側だった
```

**ただし方向は両面ある。** 既定の `--yardstick standard` では、帯を移すと穴はむしろ**縮む**
（26本平均 11.3041 → 4.5941点）。CO₂ と O₂ が容積に対して逆符号だからである。
文書はこの数字を自分の表に持ちながら、判断1 の理由に反映していなかった。

**結論: 移し先は `reference_limits` ではない。** 却下は維持するが、
**第3案（運用の帯 104.25 をリテラルで `plant_sim.survival` 部分木の内側に置く）は未決に戻る** —
落とした理由が撤回1 の 0.07 だったため、却下が無効になった。実測で:

```
                        公表値の容積依存   生存24本の幅   ルール腕−no-op(B軸O₂)
現状                        0.000            0.0000           +0.0000
reference_limits に移す     依存する         0.3459           +0.0716
survival 部分木にリテラル    0.000            0.3459           +0.0716
```

# 第2部 — 提案と無関係に、生きた穴が4つあった

**破れ1〜3（EXP-021）を塞いだ扉の横に、掛け金の無い窓が4つ空いていた。**

## 破れ6 — `--steps` は両方のガードに存在しない（**最大かつ最安**）

```
何もしない腕を step 数だけ変えて走らせた（--actor-mode none）
  50 step   69.4 / 90     ← 公表 no-op
   2 step   86.1 / 90     ← 公表ルール腕 84.35（標準物差し）を +1.75 上回る
  scoring_bar_modified = []   operating_point_modified = []   警告行ゼロ
```

原因は `scenario_run.py` の `_OPERATING_POINT_IGNORED = {"simulation.steps", "simulation.seed"}`。
**seed は「決定的な腕に届かない」と EXP-021 が実証したが、steps はその根拠を共有していない。**
steps は採点の分母そのもので、`_score_a` が CO₂ 曝露と O₂/水 の不足を `帯 × steps` で割る。
**短く走らせれば、汚れる時間が短いだけで点が上がる。**

**EXP-021 の 90.000点 no-op は `--set` 4本＋⚠表示付きだった。これはフラグ1本・警告ゼロである。**

## 破れ7 — 容積に入力検証が無い

```
ea scorecard <run> --habitat-volume-m3=-5   → B 資源余裕 20.0/20 満点
                                              カードは「NASA-STD-3001 at -5 m3」と印字
ea scorecard <run> --habitat-volume-m3 0    → 黙って 388 に戻る（`if habitat_volume_m3` が falsy）
```

負の容積では帯が負になり、あらゆるピークが「帯より下」になって余裕が満点になる。
**間違った読みではなく、読みが存在しないものを、規格の名前を冠して印字していた。**

## 破れ8 — 既定の物差しがガードを表示しない

```
同じ物理・同じ乗員損失（2/4）で、thresholds の警報線だけを 99999 にした場合
  --yardstick run       拒否される
  --yardstick standard  48.93 → 52.77 / 90（+3.84点）。**画面にも JSON 表示にも何も出ない**
```

`standard` では CO₂ が NASA 側で採点されるので `thresholds` は**ブロックしない**。
しかし `thresholds` は減員が読む健康状態を決めるので、**警報が鳴らないだけで critical step が 0 になる。**
**既定の物差しほどガードが緩い**という向きになっていた。

## 破れ9 — 判断3-a は実装前に破れた（置き場所の選択そのもの）

```
plant_sim.habitat.volume_m3 = 3000
  → scoring_bar_modified（拒否）   = []                              ← 拒否しない
  → operating_point_modified（表示）= ['plant_sim.habitat.volume_m3']

plant_sim.survival.habitat_volume_m3 = 3000
  → scoring_bar_modified（拒否）   = ['plant_sim.survival.habitat_volume_m3']  ← 拒否する
```

設計文書は「見立ては物差し＝拒否側」と書きながら、推奨した実装は**表示側**だった。
さらに「CLI と食い違えば表示する」は**食い違わない場合を守らない** —
run が 3000 を名乗り採点者が何も指定しなければ、今日フラグを打ったのと同じカードが出て、
しかも**run に焼き付いて以後の再採点すべてに付いてくる。**
**可視性は上がらず、持続性だけ上がる。**

## 教訓

**EXP-021 の教訓（「無料で確かめられる弱点は出す前に自分で確かめる」）を実行したが、足りなかった。**
確かめはしたが、**確かめた検定を現状にも当てなかった。**片側にだけ物差しを当てれば、
どちらを却下したいかで結論が決まる。

**そして向きが逆の同じ誤りがあることを学んだ。**
EXP-016・EXP-020 は「**動かない軸を動かしたい**」動機で誤った。
EXP-022（本件）は「**動かさなくてよい**」動機で誤った。
**却下は作業が減るので、慎重さの外見をまといながら同じ構造の誤りが通る。**
「これは4回目の候補だ」という自戒そのものが、その通過を助けていた。

**追加する規律: 変更を却下する検定は、現状にも当てて併記する。**

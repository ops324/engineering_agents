## ★ いちばん重い発見 — 生存者数は「打ち切られたカウント」である

これは案3 に限らず、**この評価層で生存者数を主指標に使ったすべての測定に効く。**

```
著者が選んだ運用点（初期O2 91.8〜94.0 / 初期水 51.5〜53.0）の 20 セル
steps=50    oracle 64 / 最良の単一定数 60 / 余地 4
steps=100   **全セル・全定数で 0 人**
steps=200   **0 / 480。ひとつの例外もなく全滅**
```

**「厳しいが生存可能な点」だと思っていたものは、単に全滅する点だった。**
50 step で切ると「その時点までに何人死んだか」が記録され、それを「生存者数」と呼んでいた。
**内点も「判断の余地」も、打ち切りの副産物である。**

機構は素直だ。水は全 run で **49.8〜50.0 L**（在庫 52 L に対して 0.4% の幅）を漂い、
帯 50.0 L を2 step 連続で割るたびに1人ずつ失われる。死は step 40 以降にしか起きない。
**測っていたのは「生き延びられるか」ではなく「何 step 目に死ぬか」だった。**

**打ち切りに強い指標で測り直すと余地は縮む:**

```
指標                    天井    oracle   最良定数   余地
生存者数（著者）          80       71       60      11（18.3%）
person-steps           4000     3793     3712      81（**2.0%**）
```

**新しい規律: 生存者数を主指標にする前に、観測窓を2倍にして結論が生き残るか見る。**
数分・GPU 0秒で済む。

## ★ 案3 が成立しない理由（3つとも独立）

### 理由1 — 状況を一切見ない定数が満点を取る（著者自身の撤回条件2 が発火）

著者は `agents.actor.policy.ogs_goal.input_water_mass` **1本だけ**を掃引した。
**政策キーを3本にすると、状況を見ない単一の定数が 20 セル全部を取る:**

```
ogs_goal.input_water_mass = 0.08 / wrs_feed_trigger_l = 0.0 / co2_action_margin_kg = 0.6
          O2 91.8  92.0  92.5  93.0  94.0
初期水51.5      4     4     4     4     4
     52.0      4     4     4     4     4
     52.5      4     4     4     4     4
     53.0      4     4     4     4     4
                              合計 **80 / 80**（著者の「上限」は 71/80）
peak CO2 の最大 1.460（警報線 2.0）  ← 他の軸を犠牲にしていない
scoring_bar_modified = []            ← 物差しは動いていない
```

**著者が測定前に書いた撤回条件2**（「単一の定数が全セルで最良タイ以上 →
EXP-026 と同じ1ビットであり不成立」）**がそのまま発火する。**

機構も素直で、監査によれば **CO₂ に先手を打つと捕集 CO₂ が常に手元にあり、
Sabatier が電気分解の水の約半分を返すので、OGS の水コストが半減する。**
状況に依存しない設計則である。

**「余地 11 人」は状況の幅ではなく、政策空間を1次元に絞ったことの関数だった**
（1鍵 11 → 2鍵 9 → **3鍵 0**）。

### 理由2 — 後知恵を除くと 6 人で、しかも1ビットで取れる

「11 人」は各セルの結果を**見てから**最良を選んだ合計である。
監査が leave-one-cell-out で測り直した:

```
規則の複雑さ              手元の点   交差検証
0ビット（単一定数）          60       60.0
1ビット（初期水に閾値1本）    69       **66.0**
2ビット                    71        65.5   ← 悪化
完全参照表                 71        60.0   ← 汎化ゼロ
```

**正直な余地は +6 人で、その全部が「初期水が 51.5 L 以下なら水を使うな」という
閾値1本＝1ビットで取れる。** EXP-026 の失格基準そのものである。

### 理由3 — 「共通集合が空」は環境ではなく箱の性質

シナリオ自身の帯を張る中立格子（初期O2 92→104・初期水 52→80）では
**共通集合は空ではない**（`{0.040, 0.070, 0.075, 0.080, 0.110, 0.115}`、余地 0）。
既定の運用点は初期O2 **104.86** / 初期水 **80.0** で、著者の箱はそこから大きく外れた枯渇域だった。

## 著者の誤り（すべて再現済み）

### 誤り1 ★「OGS のラッチはバグに見える」は、リポジトリ自身の記録に反する

commit `3cf84ea` が **OGS を名指しで検討して、意図的に残している**:

> Not changed, **and checked**: OGS keeps its one-shot latch, which is still sound at
> **2.753x margin**, and WRS never had one.

ARS が直されたのは「定格の不変条件のもとで 1.08 step 分しか除去せず、一発では何も回復しない」から。
**同じ基準を OGS に当てた結果、2.753倍で合格していた。**
「同じ修正が当たっていない」のではなく、**同じ基準を当てて判定が分かれた**のである。

さらに同じコミットは、著者が提案しようとしたまさにその変更を ARS について見送っている:

> Running ARS every step regardless of band does better still. **Not taken: it removes the
> rule arm's reactive character, and the arm exists to be a judgement-shaped baseline.**

**著者は 330行と 369行の2行だけを並べ、OGS 側の等価物（289〜299行の再武装分岐）と
コミット履歴を読んでいなかった。** 正しい要約は「OGS は**前回の一撃が効かなかったときだけ撃ち直す**」で、
「発火中は撃たない」ではない。

### 誤り2 ★「直せば公表値 82.2297 が変わる」は誤り

一時 patch を当てて実測し、必ず戻した（リポジトリは clean）:

```

ルール腕・故障あり  69.7382   69.7382   0.0000

**動かない。** 既定の運用点では初期O2 が発火線の上にあり、ラッチの挙動が出番を持たないため。

費用を過大に、便益を未測定のまま出していた。**

### 誤り3 — 「櫛の真因はラッチ」は半分だけ正しい（監査2体が割れ、両方正しかった）

```

**著者はこの2つを1つの説明にまとめてしまい、しかも「環境は健全で実装が悪い」という

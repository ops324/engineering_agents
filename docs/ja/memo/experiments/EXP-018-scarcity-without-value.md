## 予測（測定前にコミット・手順ルール5）

> **P1: 案1 単独では判断は生まれない。f と同じく退化する。**
>
> 根拠は EXP-017 の baseline 表そのもの。`o2_worst` `o2_terminal` `water_worst`
> `water_terminal` は**すでに満点**（各 3.000）で、空いているのは CO₂ 側だけである。
> 満点の軸に指令を1つ足しても 0点しか増えない。したがって予算 N をどう配っても

**P1 は当たった。以下はすべて自分のコマンドで測った数字である。**

## 1. 指令の 54% は 0点である

乗員4・50 step・seed 101・plant_sim・決定的:

```
run             止めたもの                    共通3軸/90    B/20      o2_w  wat_w
base            —（参照）                       82.2297   12.2378   3.000  3.000
noWRS           WRS の発火                      82.2297   12.2378   3.000  3.000
noWRS_noOGS     WRS の発火 ＋ OGS の産出        82.2297   12.2378   3.000  3.000
noop            腕そのもの                      68.6661   12.0000   3.000  3.000
m100            —（常時 ARS・margin 1.0）       85.2628   15.2628   3.000  3.000
```

`base` の指令は **ARS 37 / OGS 14 / WRS 30 = 81件**。
そのうち **44件（54%）を丸ごと無効化して、共通3軸は小数4桁まで一致する。**

**OGS と WRS の指令には限界価値が無い。**

### なぜ 0点なのか — 帯が遠い

B の O₂ は**発火線 104.25 kg ではなく生存帯 91.31 kg** で採点されている（水は 50.0 L）。

```
              min（base）   min（OGS/WRS 停止）   採点の帯    余裕
O₂            104.21 kg      102.57 kg           91.31 kg   11.3 kg
水（final）     78.16 L        73.79 L            50.0  L    23.8 L
```

50 step の可動域が帯までの距離に届かない。**EXP-017 の「O₂・水は窓内で帯に届かない」を
再現したうえで、それが採点上ちょうど 0点であることまで確かめた。**

## 2. 予算はそもそも縛らない

価値があるのは ARS だけである。ではその ARS は 1 step に何件出るのか:

```
base （margin 0.0）  ARS 1件の step 37 / 0件の step 6      → 最大 1/step
m100 （margin 1.0）  ARS 1件の step 50 / 0件の step 0      → 最大 1/step
```

**常時 ARS の極限でもちょうど 1/step。** 定格の不変条件が同一 step の合算を止めるので、
2件出しても意味が無く、腕も出さない。

したがって **予算 N ≥ 1 を入れても、価値のある行動は一度も削られない。**
削られるのは 0点の OGS/WRS だけで、それは点に影響しない。

**案1 は「奪い合うもの」を作るが、奪い合う価値が片側にしか無い。**
f が退化したのは**代償が無い**からで、案1 が退化するのは**代替の使い道に価値が無い**から。
形は違うが、症状は同じ「内点の最適が無い」である。

## 3. 効かなかった道具（記録）

**`o2_storage_low_kg` で OGS を止めることはできない。** `THRESHOLD_POLICY_KEYS` に入っており
`merge_labeled_policy_from_thresholds` が `thresholds` の値で policy を**上書きする**。
`thresholds` 側を動かすと `scoring_bar_modified` が立ち、run 自身の閾値で採点できなくなる
（EXP-016 の訂正で入れたガード。ここでも正しく働いた）。
**OGS を止めるなら産出（`ogs_goal.input_water_mass`）を 0 にする。**

**`--actor-mode none` を代用にしないこと。** no-op は乗員を1人失うので代謝が落ち、
O₂ の落ち方が**遅くなる**（min O₂: noop 102.98 > noWRS_noOGS 102.57）。
乗員4を保ったまま OGS/WRS だけ止めるほうが厳しい側の測定である。

## 結論

**案1（希少性1）は落ちた。** 残るのは3案:

| 案 | 内容 | EXP-018 を受けての見立て |
|---|---|---|
| ~~1~~ | ~~行動数の上限を指令数に効かせる~~ | **退化（本実験）。予算が縛らず、代替に価値が無い** |
| 2 | 行動に費用を与える（電力予算を3系統で共有） | 代償を作る。ただし**費用を払う先に価値が無ければ同じ穴** |
| 3 | 運用点を締め、O₂ と水が窓内で帯に届くようにする | **本実験が示したのはまさにこれが欠けていること** |
| 4 | 故障に回復コマンドを入れる | c が成立する。R4 と同じ構造 |

**案2 は単独では案1 と同じ理由で落ちる可能性が高い。** 電力を共有させても、
O₂ と水が満点で張り付いている限り「電力を ARS 以外に使う理由」が無い。
**案3（帯に届くようにする）が他の案の前提になっている**というのが本実験の含意である。

順序として、**案3 → 案2 または案4** が筋が通る。ただし案3 は全 run が比較不能になる。

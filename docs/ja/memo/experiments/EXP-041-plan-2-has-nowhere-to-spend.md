## なぜ測ったか — 却下の論証が円環していた

案2 は EXP-017 の4案のうち**唯一、一度も測定されていなかった**。
EXP-018 は散文でこう却下している:

> **案2 は単独では案1 と同じ理由で落ちる可能性が高い。** 電力を共有させても、
> O₂ と水が満点で張り付いている限り「電力を ARS 以外に使う理由」が無い。

**これは結論を前提に使っている。** 「O₂ と水が満点」はこの運用点の性質であり、
案2 はその運用点に費用構造を足す提案なので、**足したあとに何が起きるかは測らないと分からない。**
`STATE.md:837` 自身が「EXP-018 の却下は散文で、論証が円環していた」と書いていた。

## ★ 先に分かったこと — 電力はこのシミュレータに存在しない

```
grep の結果  plant_sim にも src/scenario/ssos_eclss_loop/scenario.yaml にも power / eps / watt が無い
             EPS は ros2 側の別シナリオ（scrubber_degradation）にしかない
⇒ **案2 は `--set` の掃引では測れない。実装が要る。**
⇒ だから**実装を払う前に S1**（EXP-026/027/040 と同じ規律）
```

## 方法 — 実装せずに「予算の配分」だけを模擬する

電力そのものは無くても、**「どの系統に活動を割り振ると何点買えるか」**は測れる。
これが配分問題の全内容である。

```
格子 36 セル（決定的・seed 101・steps 50）
  ARS  agents.actor.policy.co2_action_margin_kg  ∈ {0.0, 0.3, 0.6, 1.0}
  OGS  agents.actor.policy.ogs_goal.input_water_mass ∈ {0.00, 0.15, 0.30}
  WRS  agents.actor.policy.wrs_feed_trigger_l    ∈ {1e6（＝完全停止）, 0.5（既定）, 0.1}
実際に使われた指令数は summary.commands.applied から読む（＝「使った電力」の代理）
ガード  scoring_bar_modified [] / operating_point_modified [] （全セル）
       **arm_modified は非空**（腕の政策を触っている）⇒ 公表値 82.2297 と同じ表に並べない
```

## 結果

```
表1  スコアは ARS のマージンだけの関数
 ARS margin   共通3軸    ARS回数   OGS回数の範囲   WRS回数の範囲   その中でのスコアの幅
     0.0     82.2297      37        14-36          0-49        **0.0000**
     0.3     82.9728      39        14-36          0-49        **0.0000**
     0.6     84.1972      44        14-36          0-49        **0.0000**
     1.0     85.2628      50        14-36          0-49        **0.0000**
全 36 セルで乗員 4/4。**異なるスコアは4種類しかない**（＝ARS の4水準）

表2  限界価値 — 1系統に「電力」を回して何点買えるか
  ARS （指令 37 → 50回）    **+3.0331 点**   ← 天井までの余地の全部（EXP-029 の 3.03 と一致）
  OGS （指令 14〜36回）     **+0.0000 点**
  WRS （指令 0 → 49回）     **+0.0000 点**   ← 完全に止めても点が動かない
  ★2026-08-30 監査で限定: **この格子では水が拘束されえない。** 窓50・初期水 80.0 L で
    最終水は 72.78〜79.63 L、閾値は 50.0 L ＝ **最も使った run でも 22.78 L の余裕**。
    EXP-043 の式では窓50 の崖は **51.23 L**。初期水 80.0 はその **28.8 L 上**。
    ⇒ 「WRS の限界価値 0」は**測定というより、この運用点の恒等式**である。
      **結論（案2 は案3 に依存する）はむしろ強まるが、「WRS を止めても平気」は一般化できない**
```

**⇒ 予算を3系統で共有しても、ARS 以外に回した分は1点も買わない。**
**どの予算 B でも最適は「ARS が使い切れるだけ渡す（上限 50回＝1 step に1回）」で、残りは無関係。**
**＝ 配分の判断が存在しない。案2 は単独では退化する。**

**★ 結論は EXP-018 の散文と同じだが、根拠が入れ替わった。**
EXP-018 は「O₂ と水が満点だから」と**結論を前提に**使った。
本測定は前提を使わず、**限界価値を直接測って 0.0000 を出した。**

## ★ 著者の解析が一度、逆の判定を出した（自己訂正・記録として残す）

初版の `analyse.py` は「予算 B ごとの最良セル」を出し、**すべての B で「内点」と判定した。**
誤りである。

```
機構  `ogs_goal.input_water_mass=0.0` は OGS を**止めない。**
      1回あたりの効果を 0 にするだけで、腕は撃ち続ける（14回 → **36回に増える**）
     ⇒ 「ARS だけに配る」セルが格子に存在せず、最良セルが必ず OGS>0 になっていた
規律  **格子に無い選択肢を「選ばれなかった」と読んではいけない。**
      EXP-028 の「格子が結論を作った」（1 L 刻みで窓 0.5 L を測った）と同じ族である
```

**表を読んで気づいた** — 36セル中スコアが4種類しかなく、それが ARS の4水準と一致していた。
**判定を捨てて限界価値に書き換えた。** 誤った判定は公開していない。

## ★ 副産物 — 効果 0 の指令を撃ち続ける腕がある

`input_water_mass=0.0` にすると OGS 指令が **14 → 36回に増える。** 1回も何もしないのに。

**⇒ 指令数を指標に使うと、悪化が改善に見える。**
EXP-016 が C 軸について見つけた「発行指令数と相関する（v5 r=−0.629）」と同じ族。
**`effective_rate.py`（有効提案率）が designer 層で解いた問題が、actor 層にも同じ形である。**

## 言えること / 言えないこと

```
言える  ① 現行の運用点では、案2 に配る先が無い。限界価値は OGS も WRS も **0.0000**
        ② WRS は**完全に停止**しても点が動かない（発火点 1e6 で指令 0回）
        ③ 案2 は案3 に依存する。**案3（運用点を締めて O₂/水 が窓内で帯に届くようにする）が
          先に成立しない限り、案2 は測る意味を持たない**

言えない ④ **案3 の下での案2。** 締めた運用点では O₂/水 に価値が生まれる可能性がある。
          本測定は現行の運用点についてしか言っていない
        ⑤ **OGS を完全に停止した場合。** そのセルは格子に無い（このノブでは止まらない）。
          止めれば点が下がる可能性は否定していない — だがそれは「最低限が要る」であって
          「配分に価値がある」ではなく、**判断にはならない**
        ⑥ 窓 50 のみ。EXP-037 の規則（窓を倍にして生き残るか）は当てていない
```

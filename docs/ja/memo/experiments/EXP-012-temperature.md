## 問い

EXP-011 で**予測していなかった観察**が出た。

```
person-steps   labeled_rule_base（決定的）  200
               llm t=0.45                185.8 ± 11.9  (n=5)
               llm t=0.0                 168.8 ± 10.7  (n=5)
               none（決定的）              164
```

**温度 0.0 の腕は、何もしない腕とほとんど変わらない。** ただし事後的に気づいた比較で n=5 だった。

**これは今後すべての実験の前提になる設定**なので、先に決着させる。

## 解析方法（結果を見る前に固定する）

- 主指標: **person-steps**（EXP-011 でノイズ床 CV 6.4%、必要 n 約7/arm）
- 検定: **Welch の t 検定、両側、α=0.05**、n=7/arm
- 効果量は平均差と 95%CI で報告する。**検定を後から選ばない**
- 副指標（判断には使わないが必ず報告する）: peak CO₂、o2_steps_below、o2_min_kg、crew_remaining、生存者数

## 予測

| # | 予測 |
|---|---|
| P1 | t=0.45 の person-steps 平均 > t=0.0 の平均（EXP-011 の観察が追試される） |
| P2 | 差は 15〜20 person-steps 程度（EXP-011 では 17.0） |
| P3 | t=0.0 の平均は no-op 腕（164）と**有意に区別できない** |
| P4 | どちらの条件も全 run で telemetry が異なる（再現しない） |
| P5 | 分散は温度で変わらない（EXP-011 の F 検定 0.82 の追試） |

## 決め方（事前に宣言する）

- **p < 0.05 かつ P1 の向き** → 今後の実験は **temperature 0.45** で回す
- **有意でない** → 温度は性能に効かないものとして、出荷既定の 0.45 を使う（変更の根拠が無いため）
- **逆向きに有意** → 0.0 を採用し、EXP-011 の観察は偶然だったと記録する

いずれの場合も**結論は記録する**。

## 副産物① — ノイズ床が過小評価だった

**この実験の規模を決めた数字が、この実験によって否定された。**

```
                                    SD     CV      必要n /arm
EXP-011（10 run）                 11.32   6.4%        6.5
EXP-012（合格 11 run）            21.79  12.7%       25.9
両者を合わせた LLM 腕 21 run      18.29  10.5%       17.7
```

**n=7 では足りない。18〜26 が要る。** EXP-011 の 95%CI は [3.0, 24] だったので、
**当時から上限は 24 を含んでいた**（点推定だけを見て 7 と読んだのが甘かった）。

### なぜ過小評価になったか — 分布が二峰である

```
person-steps の分布（合格 11 本）
  117  ■
  164  ■■■■     ← no-op 腕（決定的）の値と完全一致
  173  ■■
  188  ■
  189  ■
  192  ■
  195  ■
```

**両実験を通じて 21 本中 8 本が、no-op 腕とまったく同じ 164 に着地している。**
正規分布を仮定した SD 推定は、この離散的な「何もしなかったモード」を n=5 では取りこぼす。

## 副産物② — LLM は CO₂ 除去装置を動かさないことがある

164 に張り付いた run のコマンド内訳:

```
t045_r1  50コマンド  適用18/拒否32  内訳 oxygen_generation 18   ← ARS ゼロ
t045_r4  67コマンド  適用64/拒否 3  内訳 oxygen_generation 64   ← ARS ゼロ
t00_r6   59コマンド  適用 0/拒否59  内訳 なし
t045_r6  66コマンド  適用66/拒否 0  内訳 OGS 59 + ARS 7        ← peak 2.270、良い run
```

**CO₂ が基準を超えて上がり続けているのに、スクラバーを一度も動かさない run がある。**
酸素生成ばかり発行している。ARS を7回でも出した run（`t045_r6`）は peak 2.270 に抑えている。

`t00_r6` はさらに極端で、**59回すべてが `request_co2`（ARS の回収タンクから CO₂ を要求）で、
59回すべて「partial: insufficient co2」で失敗**している。ARS を動かしていないので回収タンクが空であり、
**空のタンクに50ステップ要求し続けて、一度も行動を変えていない。**

EXP-003 の「本物の doctrine ギャップ（故障を観測しても行動を変えない）」と同じ形が、故障なしの条件で出た。

## 副産物③ — 3/14 が定格超過で証拠として不admissible

```
t00_r4   ARS 14.38x rated
t045_r3  ARS 13.38x
t00_r7   ARS 10.80x
```

機構を分解した（`t00_r4`）:

```
4.00x  ars_operation_seconds 4800 ÷ step_seconds 1200   （B4。EXP-004 の未適用分）
1.798x goal scale = initial_co2_mass 3.236 / reference 1.80
2x     同一 step に2エージェントが発行（max_actions_per_step: 2）
────────
14.38x  ← ゲートの報告値と完全一致
```

**コマンド経路には goal の上限が無い**（NaN/Inf/負値だけを弾く）。`6153193`
「deterministic admissibility gate on the command path」は**構造的な拒否**
（エージェントが自分の故障注入を切り替えられない等）であって上限ではないので、cherry-pick しても直らない。

物理ゲートが事後に捕まえている。**ゲートは仕事をしている**が、3/14 が捨てられるのは実験効率として重い。

## 結論

- **温度は性能を変えない。** 出荷既定の 0.45 を使う（事前宣言どおり）
- **必要 n は 18〜26/arm。** 7 は楽観だった。腕の比較には LLM 側だけで約3時間かかる
  （ルール腕は決定的なので1本でよい）
- **LLM 腕の分布は二峰**で、21本中8本が「何もしないのと同じ」に着地する。
  平均だけを比べる設計は、この構造を隠す
- **ARS を一度も動かさない**という具体的な失敗の形が見えた。これは温度ではなく doctrine の問題
- **定格超過が 21% の run で起きる。** goal の上限が無いことと B4 が掛け算になっている

# 第1部 — 撤回条件が、実装前に、手持ちのデータで既に発火していた

設計文書 §6 に先に書いた撤回条件のうち**2つ**が、実装前に成立していた。

## 撤回条件1 —「乗員が減ると点が上がる run が1本でも出たら戻す」

```
EXP-019 の対応する組（違いは CO₂ の期限だけ・同一腕）
  m0.0_e13    乗員 4/4  提案 5.9986      m0.0_e14    乗員 3/4  提案 5.9988
  end13       乗員 4/4  提案 5.9986      end14       乗員 3/4  提案 5.9988
  m0.15_e13   乗員 4/4  提案 5.9986      m0.15_e14   乗員 3/4  提案 5.9988

60本の群平均   乗員3/4 = 5.9954  >  乗員4/4 = 5.9945   （向きが逆）
交差対 731 のうち 535 で、乗員の少ない run が勝つ   （現行の帯では 0 件）
```

**機構は物理である。** `plant_sim/model.py` は O₂ 需要を生存乗員数に比例させる。
`ref_none` の実測で、乗員喪失を境に減りが **−0.046667 → −0.035 kg/step** に変わる。
反実仮想（誰も死なない場合）と比べた**死の報酬は +0.0234点**で、
**EXP-019 で提案が稼いだ分解能の全幅 0.0237 とほぼ同じ大きさ**である。

**そしてこれは提案に固有である**（こちらで追加検定した。監査は指摘していない）:

```
軸              乗員3/4   乗員4/4   判定
B軸 CO₂          0.3003   0.4520   乗員が多いほど高い
A軸 CO₂          7.8690   7.9963   乗員が多いほど高い
B軸 水           6.0000   6.0000   定数
提案の B軸 O₂    5.9954   5.9945   ★ 逆
```

CO₂ には「CO₂ が悪いから乗員が死ぬ」という因果があるので群の向きが正しく出る。
**O₂ にはその因果が無い**（EXP-019 の死因は CO₂）。残るのは代謝経路だけで、
**提案の帯は、死を報う経路しか持たない。**

## 撤回条件4 —「OGS を回さない腕が回す腕より高い点を取る集合が出たら戻す」

`--set simulation.initial_o2_storage_kg=106.2` の**ノブ1本**（+1.28%）で成立する:

**買える +0.0910 は、この変更が作る信号の全額（ルール腕 − no-op = +0.0894）より大きい。**

**★ そして現行の帯では同じ攻撃の差が 0.0000 である。**
**飽和は失われた分解能であると同時に、免疫でもあった。** 設計文書はこの側面を見ていない。

# 第2部 — 判定基準そのものが機能していなかった

## 基準2（p < 0.01）は、このデータでは原理的に到達できない

「OGS 指令が多い群」の「多い」を定義していなかった。完全列挙で:

```
カット        n      差        完全検定 p
OGS>= 1 vs 0  18/6  +0.0241   0.48539   ← 唯一「選ばなくてよい」読み方。落ちる
OGS>= 2 vs 0  16/6  +0.0267   0.47287
OGS>= 4 vs 0  13/6  +0.0523   0.00007
OGS>=11 vs 0  10/6  +0.0630   0.00012   ← 文書が使ったカット
OGS>=40 vs 0   3/6  +0.0548   0.01190
```

**有意にするには OGS を少しだけ使った run を捨てる必要があり、それが反例そのものである。**

さらに**擬似反復**があった。OGS=0 群 6本のうち **5本は O₂ 軌跡が同一**である:

```
軌跡 (102.981667, 102.981667) → 5本  [llm_r10, llm_r13, llm_r5, llm_r6, ref_none]
軌跡 (102.970000, 102.970000) → 1本  [llm_r8]
重複を畳むと n=10/2 → 完全検定で到達できる最小 p = 1/66 = 0.01515
```

**基準2 と基準4 が、同じ5本を、一方では5標本・他方では1軌跡として数えていた。**

## 基準4 は、この軸に対して反証不能

B軸O₂ は `(min, terminal, 帯)` の純関数なので、**同一の O₂ 系列を分離することは数学的に不可能**である。
現行でも提案でも必ず通る。EXP-016 が C 軸を落とせたのは、C が軌跡の外（発行指令数）を読んでいたから。

## 基準1・2 は 104.2492 を選べない — 出典の無い帯のほうがよく通る


# 第3部 — 自分の誇張と、引用しなかった反対証拠

## 誇張:「現行は 91 run すべてで一つの値」→ 実際は3値

```
全91本  {6.0000 × 89, llm_r15 5.9128, llm_r23 5.8542}   異なる値 3・幅 0.1458
正しくは「**生存 89本で**一つの値」
```

**EXP-022 が1日前に訂正したのと同じ2本・同じ型の誇張を、判断を運ぶ地の文で再掲していた。**

## v4 の除外は、そもそも計算が誤っていた

設計文書は v4 を「O₂ が 8 kg のタンクなので適用外」として除外したが、**その判断に使った数字は、
v4 に 91.31 を外から当てて出したもので無意味だった。** 正しく **run 自身の帯（6.0）**で採ると:

```
v4 26本   帯は全て 6.0   全体: 異なる値 5・幅 6.0000   生存21本: 異なる値 2・幅 0.0298
```

**⇒ v4 でも現行の帯は生存者をほとんど分離しない。**
除外の結論は変わらないが、**定数性は「帯の欠陥」ではなく「この物理での軌跡の位置」の性質**である。

## `scenario.yaml` が、論拠を2つとも明文で否定していた（引用していなかった）

```
114行  CO₂ と水の帯が閾値と同値なのは "on purpose"。
       ⇒ どちらの段で測る規則かの情報を **1ビットも持たない**
129行  O₂ の帯に 50 step で届かないのは "That is intended"。
       "O2 should become lethal through a leak (roadmap R4), not through breathing"
```

## コードが従っている規則は、文書が書いた規則と違う

```
score_run(ref_rule, habitat=None)             B の co2_limit_kg = 2.0
score_run(ref_rule, habitat=SCENARIO_HABITAT) B の co2_limit_kg = 2.78307894  ← NASA@388
両方とも                                       B の o2 band_low = 91.31、water = 50.0
```

**B軸 CO₂ は `thresholds` ではなく yardstick から来ている。** 水が警報の段に見えるのは
2つの数字が一致しているだけ。**実装が従う規則は「余裕は減員の帯で測る（CO₂ だけ標準から）」であり、
提案はそれを O₂ だけ破る。** 「規則の適用であって新しい価値判断ではない」は成立しない。**R3 の領域である。**

## 置き場所（案A）は、名指しした1箇所を直しても素通りする

```
plant_sim.margin_bands を動かした run
  _scoring_bar_modified に追加した場合   → run では拒否、**standard では拒否しない**
```

`score.py:499` の `unscorable_either_way` が `plant_sim.survival` / `plant_sim.habitat` を
**べた書き**しているため。**文書は直す場所を1つしか書いていなかった。**
**EXP-021 の「逃げ道として案内した先が、ガードの無い方だった」と同型である。**

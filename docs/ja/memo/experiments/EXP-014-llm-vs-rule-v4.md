## 予測を書き直した理由 — 比較が公平でなかった

**最初の事前登録（`b63160c`）は無効にした。** LLM 腕の条件が変わったためである。

走らせ始めてから、**LLM 腕が WRS の存在を知らされていない**ことが分かった。
`_ECLSS_OPERATIONAL_LEVERS` に `water_recovery` が無く、ペルソナも「ARS と OGS を
coordinate せよ」としか言っていない。さらに観測文字列に `urine_buffer_l` が無く、
**ルール腕が WRS 起動の判断に使っている読み値そのものが見えていなかった**。

```
ref_labeled_rule_base   ARS 37 / OGS 3 / WRS 30   ← 3系統を操作
llm（v3 EXP-013 の24本） water_recovery ……… 0回   ← 24本中0本
llm_r1（v4・修正前）     ARS 51回のみ、OGS も WRS も0回
```

これでは「AI はルールより上手いか」ではなく
**「情報を減らされた AI は、全部知っているルールより上手いか」**を測ることになる。
**EXP-013 の結論も、一部はこの非対称で説明できてしまう。**

直したもの（プロンプトのみ。物理・採点は無変更）:

1. levers に `water_recovery`（payload `urine_volume`）を追加
2. 観測文字列に `urine_buffer_l` を追加
3. ペルソナに WRS を追加

**ルール腕の閾値（CO₂ 2.0 / 8.0 kg）は与えていない。** LLM が受け取るのは
`warning` / `critical` というラベルだけで、これは意図した設計上の非対称として残す。

### 正直に記しておくこと

**予測を書き直す前に `llm_r1` を1本見てしまっている**（共通3軸 69.681・乗員3/4・
ゲート合格）。したがって下の予測は**完全な盲ではない**。ただしその1本は WRS を
知らない条件のものであり、書き直した予測は WRS を知る腕についてのものである。
無効にした run は `~/ea-runs/2026-08-27-v4-VOID-incomplete-levers/` に理由つきで残した。

## 予測 v2（**levers 修正後・走らせる前に書いた。走らせた後に書き換えない**）

**P0 を最初に置く。これが今回いちばん知りたいことになった。**

### P0 — LLM 腕は WRS を使うようになる

教えれば使うのか。**予測: 24本中 18本以上が `water_recovery` を1回以上発行する。**

外れ方: 教えても使わない場合、これは「情報の問題ではなく判断の問題」を意味し、
EXP-013 の結論はむしろ補強される。**どちらに転んでも意味のある結果になる。**


### P1 — 物理ゲートは 24/24 合格し、`capacity_bounds` は一度も発火しない

**いちばん強い予測であり、いちばん落としやすい。** 不変条件が正しければ、腕が何を注文しても
定格を超えられない。EXP-012 では 14本中3本が `capacity_bounds` で不合格だった。
**1本でも発火したら不変条件の実装バグである。** 無料の自己検査になる。

### P2 — LLM 腕の共通3軸平均はルール腕（82.199）を下回る

**予測区間を v1 より広く取り直した: LLM 平均 62〜75点。** p < 0.05 で有意に下回る。

v1 では 60〜70 と書いたが、WRS を使えるようになるぶん上振れしうる。
根拠: ARS が1回あたり 1/4 の力になったので「動かすが足りない」失敗は v3 より重い。
注文の水増しによる救済はもう効かない。一方で水の管理は改善しうる。

**この予測が最も外れやすい。** 上に外れる（LLM がルール腕に並ぶ）なら、
EXP-013 が測っていたのは判断力ではなく情報格差だったことになる。

### P3 — LLM 腕は no-op 腕（68.666）と、やはり区別できない

**予測: |差| < 8点、p > 0.05。** EXP-013 と同じ質的結論。
ただし P0 が当たり P2 が上振れした場合、ここは崩れて **LLM が no-op を有意に上回る**
可能性がある。その場合「WRS を知らなかったことが no-op と区別できない主因だった」となる。

### P4 — 二峰性は残り、下の峰は no-op と**厳密に一致**する

ARS を一度も発行しない run は、no-op と同一の軌道になるので 68.666 ちょうどに着地する。
**予測: 24本中3本以上**がこの値（±0.01）を取る。

### P5 — 乗員残存の平均は 3.0〜3.5 人（ルール腕は 4/4）

### P6 — ゲート不合格による除外は起きないので、**採点できる run は 24/24**

v3 では注文の水増しがゲート不合格を招き、採点対象が減っていた。それが消える。

## 外れ方の候補（あらかじめ）

- **P2 が外れる形**: LLM が「毎 step ARS を出す」戦略に偶然たどり着くと、定格いっぱいで
  回すことになりルール腕とほぼ同じになる。不変条件は**下手な腕を罰するが、
  上手い腕とルール腕の差も消す**（どちらも天井に張り付くため）
- **P4 が外れる形**: ARS を出さなくても OGS/WRS の挙動差で軌道がずれ、厳密一致しない可能性
- **P1 が外れたら実装バグ。** その場合は測定を止めて不変条件を直す

## 測定範囲の制約（EXP-014 で測れないこと）

**ARS について測れるのはタイミングと頻度だけで、深刻さに応じた加減は測れない。**
goal が天井で頭打ちになったため、CO₂ が 2.1 kg でも 7.9 kg でも腕にできることは同じである。
詳細は [rated_capacity_invariant.md](../ssos_eclss_loop/rated_capacity_invariant.md) の「代償」節。

OGS・WRS の goal は「量」なので、能力の範囲内では要求量がそのまま効く。ここには分解能が残る。

## P0 — 教えれば使う。ただし半分だけで、成績は変わらない

```
v3（levers に無い）  water_recovery   0 / 24 本
v4（levers に有る）  water_recovery  12 / 24 本、総 122 回
```

行動は 0 から 12 に変わった。**しかし得点には効かなかった。**

最初、WRS 使用群のほうが低く出た（53.70 対 69.28、p=0.037）。**交絡だった。**

### 交絡の正体 — `request_o2`

全滅した4本（llm_r4・r8・r21・r23）は**全部 O₂ 死**で、**全部 `request_o2` を使っていた**。
`request_o2` は O₂ を在庫から引き出すサービス呼び出しで、**乗員が必要としている資源を
腕が自分で抜いている**。

```
request_o2 使用    6本  平均 38.82
request_o2 不使用 18本  平均 69.04     差 −30.22  p = 0.027
```

この6本を除いて WRS の効果を測り直すと:

```
WRS 使った   7本  平均 68.859
WRS 使わない 11本  平均 69.159     差 −0.30   p = 0.864  → 効果なし
```

**WRS の開示は行動を変えたが成績を変えなかった。** 水はこの運用点の律速ではない（余裕 1.50倍）。
つまり **EXP-013 の結論は情報格差では説明できない**。格差は実在したが、主因ではなかった。

## いちばん重要な発見 — 失敗は「いつ始めるか」ではなく「続けられるか」

```
最初に ARS を出した step   LLM 中央値 13   ／  ルール腕 13    ← 完全に一致
ARS を出した step の数     LLM 中央値  4   ／  ルール腕 37    ← 9倍
CO₂ 帯の滞在 step         LLM 中央値 36   ／  ルール腕  0
```

**LLM は正しいタイミングで気づいている。** 反応の遅さではない。1〜2回動かして、やめてしまう。
余裕 1.082倍では、それでは回復しない。

決定的なのは**唯一 4/4 を守った run** である:

```
llm_r12   ARS を 35/50 step で発行  →  乗員 4/4   81.995
ルール腕   ARS を 37/50 step で発行  →  乗員 4/4   82.199
```

**続けた1本だけが、ルール腕とほぼ同点になった。**
23本の敗因は判断の質ではなく**持続性**である。これは v3 では見えなかった
（v3 は ARS が4倍強く、1回で 4.33 step ぶんを除去できたので、持続しなくても成立した）。

23/24 が `co2_warning` で乗員を1人失っている。2 step 連続で帯に入ると1人失う規則なので、
**1 step 気を抜くと取り返せない**。

## 次に効く発見

1. **`request_o2` は腕が自分の首を絞められるレバーである。** 全滅4本の共通項。
   スコアカード C軸がこれを「判断ミス」として捉えられているか、確認する価値がある
2. **持続性を測る指標が要る。** 「ARS を出した step 数 / 帯に居た step 数」は
   今回いちばん説明力のあった量で、スコアカードの D軸に入る性質のものである
3. **P5 が外れたのは全滅4本のため。** 中央値（68.708）と平均（61.487）が 7 点離れている。
   二峰性のある分布に平均を当てるのが適切か、検討が要る

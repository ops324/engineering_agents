## 目的

[EXP-019](EXP-019-failure-has-no-ambiguity.md) が案4 を落とし、案3（運用点を締める）に進む前に、
**「O₂ と水が帯に届かない」のが本当に物理の問題なのか**を確かめる。
案3 は全 run を比較不能にする変更なので、払う前に確認する価値がある。

## 1. O₂ の軌跡には分解能がある

O₂ には帯が2つある。`thresholds`（運用）と `survival bands`（死）である:

```
              thresholds        survival bands
CO₂ high        2.00 kg           2.00 kg      ← 一致
CO₂ critical    8.00 kg           8.00 kg      ← 一致
O₂  low       104.25 kg          91.31 kg      ← **一段ずれている**
O₂  critical   91.31 kg          87.71 kg
水   low        50.0 L            50.0 L       ← 一致
水   critical   25.0 L            25.0 L       ← 一致
```

**規格の帯（104.25 kg ＝ [V2 6003] 正常酸素帯の下端）に対する挙動:**

```
run             最小 O₂    104.25 未満   不足積分    91.31 未満
base            104.21    14/50 step     0.35        0
noWRS_noOGS     102.57    36/50 step    30.96        0     ← OGS を丸ごと無効化
noop            102.98    36/50 step    23.61        0
```

**腕が OGS を回すかどうかで、規格の帯を割る時間が 14 対 36 step（2.6倍）変わる。**
不足積分では 88倍。**分解能は確かに存在する。**
（EXP-015 が LLM 腕で観測した「OGS 10回以上の10本は帯割れ中央 5/50」と同じ現象。）

## 2. しかし採点は 91.31 を見ており、そこは一度も割らない

`scorecard.py` は軸ごとに**違う出どころ**から帯を取っている:

```python
# CO2 は yardstick（= 実行時の thresholds を凍結したもの）から
co2_limit_kg = min(band.threshold_kg for band in yardstick.bands)   # → 2.0（運用の帯）

# O2 と水は survival bands から
inventory = inventory_metrics(run_dir, bands)                        # → 91.31（死ぬ帯）
```

`inventory_metrics` の docstring は「死が出てくる帯で採点する」と明記しており、
**これは意図された選択である。バグではない。**

**しかし帰結は意図されていない** — 同じ B 軸の中で、
**CO₂ の余裕は「運用の帯」まで測られ、O₂ の余裕は「死ぬ帯」まで測られている。**
水と CO₂ は2つの出どころが同値なので影響が出ず、**ずれているのは O₂ だけ**である。

## 3. 帯を揃えても足りない — 式そのものが鈍い

帯を 91.31 → 104.25 に揃えたらどうなるかを計算した:

```
                B o2_worst          A o2            合計の差
base            3.0000 → 2.9988   4.0000 → 3.9997
noWRS_noOGS     3.0000 → 2.9518   4.0000 → 3.9762
差（base − noOGS）  +0.0470          +0.0235        **+0.0705 点 / 90**
```

**軌跡は 2.6倍違うのに、点は 0.07点しか動かない。** 理由は式の形にある:

```python
o2_worst = 3 × min(1, min_kg / band)          # 104.21/104.25 = 0.9996。**比が1に張り付く**
A.o2     = 4 × (1 − 不足積分 / (band × steps)) # 分母 104.25 × 50 = 5212.5
                                               # 到達しうる不足は高々 31。**分母が 170倍大きい**
```

**分解能があるのは「どれだけ深く割ったか」ではなく「どれだけ長く割っていたか」である。
そしてどちらの式も深さしか測っていない。**

CO₂ が動くのは、在庫（2.05 kg）が帯（2.0 kg）と同じ桁だからにすぎない。
O₂ は在庫 104 kg・帯 104.25 kg で比が 1 に張り付き、水は在庫 78 L・帯 50 L で
**そもそも一度も割らない**。

## 結論 — O₂ と水で原因が違う

```
O₂   軌跡に分解能がある（14 対 36 step）。**採点式が深さしか見ないので捨てている**
水   50 step で一度も帯を割らない。**軌跡にも分解能が無い**
```

**案3（運用点を締める）が要るのは水である。O₂ は採点の問題を含んでいる。**

## ⚠ ここから先は物差しのハザードそのものである

「軸が動かない → 動くように採点を変える」は、**この枝が3回間違えた形**である
（[提案が物差しを動かす問題](EXP-010-crew-axis-is-not-guarded.md)、EXP-016 の撤回）。
本実験は**事実の報告に留め、採点式を1文字も変えていない。**

判断の前に:

1. **原則4 の独立監査を通すこと。** 発動条件「設計・物差し・予測が同じ手から出ている」に
   完全に当てはまる。この文書を書いた手が採点式も直すのは、まさにその構造である
2. **これは R3（配点の価値判断）の領域である。** 「余裕をどの帯まで測るか」「深さで測るか
   時間で測るか」は測定値ではなく価値判断で、[R3](R3-scorecard-weights.md) はチーム判断待ち
3. **公表値が動く。** ルール腕 82.230 は帯を揃えるだけで 82.16 前後になる（−0.07）。
   式を変えればもっと動く

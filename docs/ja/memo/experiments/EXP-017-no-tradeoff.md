## 目的

R6 の判断点として **f（帯を割る前に撃つ）** が選ばれた。実装の前に、
**決定的な腕で到達できる上限**を測る。「LLM が超えるべき線」が無いまま
3.5時間を払わないため。

## 1. 発火を早めるには、採点の帯に触れない鍵が要る

ルール腕は `co2_storage_high_kg` で撃つ。**それは採点の帯そのもの**なので、
下げると `scoring_bar_modified` に記録され、run 自身の閾値が物差しとして使えなくなる
（EXP-016 の訂正で入れたガード）。

**これは正しい挙動である。** 帯を動かして点を取るのではなく、実際に早く動くしかない。
そこで `co2_action_margin_kg`（既定 0.0 = 現状の挙動）を policy に追加した。
`THRESHOLD_POLICY_KEYS` には**入れない**。テストで固定した。

## 2. 掃引 — B は単調に上がり、最適解は「常に撃つ」

乗員4・50 step・seed 101・plant_sim・決定的:

**内点の最適が無い。** 早く撃つほど良く、極限は「毎 step 撃つ」。
**判断の余地は無く、定数政策が最適である。**

### 私の第2版設計の訂正

「B の CO₂ に **7.76点** 空いている」と書いたが、**到達可能なのは 3.03点**である
（0.238 → 3.263）。残りは ARS の定格余裕が 1.082倍しかないので物理的に届かない。
7.76 は満点までの差であって、余地ではなかった。

## 3. なぜ内点が無いのか — ARS に代償が無い

`run_ars` が消費するのは**キャビンの CO₂ だけ**である。電力も水も消耗品も引かない。
戻り値に費用の項が無い。**撃つことが無料なら、常に撃つのが厳密に支配的。**

## 4. 希少性も無い — 行動数の上限は効いていない

```
max_actions_per_step = 1   指令 ARS 37 / OGS 14 / WRS 30  合計 81
max_actions_per_step = 2   同一
max_actions_per_step = 3   同一
```

上限は「どの operator が喋るか」に掛かっており、**発行される指令数を縛っていない。**
（本家 #59 の `labeled_rule_base.md` が「max を上げても Ops が変わらない」と
書いているのと同じ症状。本家は自分たちの形で直したが、この枝の形では効いていない。）

## 5. 診断にも対処手段が無い

`subsystem_failures.py` に修理コマンドは無い。`clear_scheduled_subsystem_failures` は
時刻で消えるだけで、腕が呼べる回復手段ではない。
**ROADMAP が R4 について書いた「対処手段とセットでなければ実験にならない」が、
故障一般に当てはまる。**

そして代替も効かない — OGS・WRS を全部止めても 50 step では O₂ が約 1.8 kg、
水が約 4 L しか動かず、どちらの帯にも届かない。

## 結論 — 判断を置く場所が無いのは、腕ではなく運用点の性質である

```
撃つのは無料              → 常に撃つのが最適（f が退化）
定格超の要求は物理的に不活性 → いくつ頼むかは効かない（b が退化。EXP-016 訂正）
行動数の上限が効いていない  → ARS と OGS を competing させられない（a が成立しない）
故障に対処手段が無い       → 診断しても結末が変わらない（c が退化）
O₂・水は窓内で帯に届かない  → 資源間のトレードオフが立たない
```

**この運用点で効くのは「ARS を持続的に回す」ことだけで、それは定数政策である。**

### EXP-013〜015 の結論に、別の説明を与える

「LLM 腕は no-op と区別できない」は、LLM が下手だからだけではない。
**⚠ この前提自体が後に撤回された** — 窓 50 と粗い物差しの産物で、連続量では LLM が
no-op に有意に勝つ（[EXP-031](EXP-031-the-second-headline-was-the-window.md) /
[EXP-033](EXP-033-the-trap-and-what-it-did-not-explain.md)）。**以下の説明は「差が小さい理由」として読むこと。**
**決めることがほとんど無いからでもある。** ルール腕が no-op に 13.6点勝つのは
「持続する」からで、持続は判断ではない。

**判断を測りたいなら、腕を変える前にシナリオに代償を入れる必要がある。**

## 行き先（判断待ち・どれも物理の変更を伴う）

| 案 | 内容 | 費用 |
|---|---|---|

**どれも「AI をどこに置くか」の前に、「置く場所を作る」作業である。**

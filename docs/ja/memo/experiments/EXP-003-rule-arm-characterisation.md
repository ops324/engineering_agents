ルール腕は決定的で 0.083 秒/run。閾値を総当たりして、シナリオが
ルール設計を判別できるか（＝良いルールと悪いルールを区別できるか）を確かめる。

格子: `co2_high` 6値 × `co2_critical` 5値 × `o2_low` 5値 × `inject_failures` 2値 = 270 run / 22秒

## 付随して判明したこと

**O₂軸が既定で回路から切断されている。**
`o2_storage_low_kg: 0.45` に run 中到達しないため OGS が一度も発火しない
（`ogs_invoked_step: None`）。O₂ は単なるカウントダウン: `2.98 − 0.0467×50 = 0.65`（実測 0.69）。
`o2_low` を上げると OGS は発火する（216/270）。水軸もほぼ不動。**実質 CO₂ の1軸問題。**

**死んだ調整値**: `ogs_goal.input_water_mass: 0.15` は 0.03〜2.0 で結果不変。
理由は OGS 未発火（**null 実験**）。実際に動く条件では 0.1447 kg で飽和するので
0.15 と 2.0 は等価だが、**0.03〜0.12 は上限未満なので不変ではない**。

**偽の分解能**: 故障パターン F2（OGS恒久故障）は health が3種類に分かれるが、
`min_o2` の SD は 0.000。O₂軌跡は30通り全て同一で、動いているのは `o2_low` という
**物差しの方だけ**。スイープ時は物差しを固定すること。
